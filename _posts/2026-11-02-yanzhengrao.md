## 一、题目信息
- 平台：Pikachu
- 分类：暴力破解 -> 验证码绕过(on server)
- 难度：简单
- 通关标识：页面回显 `login success`

## 二、考点
1. 服务端验证码的逻辑缺陷
2. 验证码未及时销毁导致的重放攻击
3. 结合 Burp Suite 进行带验证码表单的暴力破解

## 三、题目内容
该关卡在原有的登录表单基础上增加了“验证码”输入框。相较于第一关，增加了一定的防护措施。但如果在服务器端对验证码的处理逻辑不当，依然可以被绕过并进行暴力破解。

## 四、解题步骤

**1. 分析验证码机制**
访问页面，输入错误的账号密码，并填入正确的验证码，点击登录。页面提示密码错误。
此时刷新页面，发现验证码变了。但如果在不刷新页面的情况下，使用刚才那个正确的验证码再次提交错误的密码，页面依然提示密码错误（而不是提示“验证码错误”）。
**这说明：服务端虽然校验了验证码，但在验证通过后，并没有立即在 Session 中销毁该验证码，导致同一个验证码可以被重复使用。**

**2. 抓取请求并固定验证码**
开启 Burp Suite 拦截，在网页上填入正确的验证码（例如截图中的 `j7eh8d`），填入任意账号密码（如 `admin` / `123`），点击登录。
捕获到 POST 请求后，将其发送至 `Intruder` 模块。

**3. 设置攻击载荷**
在 `Positions` 标签页，清除默认标记。由于我们只需要爆破密码（假设已知用户名是 admin），我们只将 `password` 的值选中并点击 `Add §`，将其设为变量。
**注意：验证码的值（如 `j7eh8d`）和 `username` 的值保持原样，不要添加 `§`。** 因为我们要利用服务端“不销毁验证码”的缺陷，对这个固定的验证码进行重放。

```http
POST /vul/burteforce/bf_server.php HTTP/1.1
Host: 127.0.0.1
Content-Type: application/x-www-form-urlencoded
Content-Length: 54

username=admin&password=§123§&vcode=j7eh8d
```

**4. 配置字典并开始爆破**
进入 `Payloads` 标签页，`Attack type` 选择 `Sniper`（狙击手模式）。
在 `Payload set 1` 中加载你的密码字典（如包含 `123456`、`admin` 等）。
点击 `Start attack` 开始爆破。

**5. 分析结果**
观察爆破结果列表。由于验证码一直是有效的，服务器会正常校验每一次请求的密码。
寻找响应长度（Length）与其他请求不同的那一条，或者直接通过返回内容寻找包含 `login success` 的请求。
找到对应的密码（如 `123456`）后，回到网页，刷新页面获取新的验证码，输入正确的账号密码和验证码，成功登录。

## 五、知识点解析
1. **服务端验证码失效机制**：正确的验证码安全逻辑应当是“一次性”的，即无论本次登录成功还是失败，只要校验过一次，就必须在服务端（如 Session 或 Redis 中）立即销毁，下次请求必须使用新的验证码。
2. **重放攻击 (Replay Attack)**：本题中，由于验证码未销毁，攻击者通过抓包固定了正确的验证码参数，利用自动化工具反复发送带有相同验证码的请求。由于服务端认为验证码正确，后续的密码校验就会正常执行，从而实现爆破。

## 六、总结与防御
**本题总结**：
验证码绕过(on server)是逻辑漏洞的典型代表。爆破的核心在于发现验证码可复用，进而抓包固定验证码参数，只对密码字段进行枚举。

**安全防御建议**：
- 验证码必须在服务端生成，并存储在 Session 等安全机制中。
- **验证码必须具有时效性和一次性**。无论登录是否成功，校验完毕后必须立即销毁。
- 限制同一 Session 或 IP 在短时间内的验证码请求频率。
- 配合登录失败次数限制，即使绕过验证码，短时间内也无法进行大规模枚举。
