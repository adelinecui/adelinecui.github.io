## 一、题目信息
- 平台：Pikachu
- 分类：SQL-Inject -> 字符型注入 (GET)
- 难度：简单
- 通关标识：通过单引号闭合绕过查询限制，成功获取全表数据

## 二、考点
1. 字符型 SQL 注入原理
2. 单引号闭合与注释符的使用
3. 联合查询（UNION SELECT）获取数据库信息

## 三、题目内容
页面提供一个输入框输入用户名进行查询。后端将用户输入直接拼接到 SQL 语句的引号内，如 `SELECT * FROM users WHERE username = '$name';`。

## 四、解题步骤

**1. 测试闭合**
输入单引号 `'`，点击查询。页面报错，说明单引号成功闭合了后端的引号，存在 SQL 注入。

**2. 注入万能条件**
输入 Payload 绕过查询限制：
```sql
' or 1=1 #
```
`'` 闭合了前端的单引号，`or 1=1` 使查询条件恒真，`#`（或 `-- `）注释掉了后端原本闭合的单引号。点击查询，页面成功回显了所有用户的信息。

**3. 联合查询获取数据库名**
- 首先使用 `' order by 3 #` 测试列数（若正常回显说明为 3 列）。
- 使用 UNION SELECT 注入数据库名：
```sql
' union select 1, database(), 3 #
```
页面回显了数据库名 `pikachu`。

## 五、知识点解析
1. **字符型注入**：输入的参数被单引号或双引号包裹。攻击者必须构造闭合 Payload，才能将恶意 SQL 语句拼接到原查询中执行。
2. **注释符**：`#` 或 `--` 用于注释掉后端 SQL 语句中剩余的代码，防止语法错误，是字符型注入必不可少的组成部分。
3. **UNION SELECT**：将两个或多个 SELECT 语句的结果组合到一个结果集中，常用于在页面有限的回显位中获取其他表或数据库的数据。

## 六、总结与防御
**本题总结**：
字符型注入的核心在于“闭合”与“注释”。只要开发者未对输入进行过滤且使用字符串拼接，攻击者就能通过闭合引号轻松注入。

**安全防御建议**：
- **预编译语句 (PDO/Prepared Statements)**：最根本的防御手段。
- **输入过滤**：过滤掉单引号、双引号、注释符等危险字符。
- **最小权限原则**：限制数据库连接账号的权限，避免高危操作。
