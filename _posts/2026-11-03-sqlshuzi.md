## 一、题目信息
- 平台：Pikachu
- 分类：SQL-Inject -> 数字型注入 (post)
- 难度：简单
- 通关标识：通过注入 `or 1=1` 绕过查询限制，成功获取全表数据

## 二、考点
1. SQL 注入基本原理
2. 数字型注入与字符型注入的区别
3. 逻辑运算符在 SQL 注入中的利用（万能密码/万能查询）

## 三、题目内容
页面提供一个下拉框选择 `userid`，点击查询后返回对应用户的信息。后端直接接收前端传来的 `id` 参数，未进行任何过滤，直接拼接到 SQL 查询语句中。

## 四、解题步骤

**1. 正常查询**
在下拉框选择 `1`，点击查询，页面仅返回 id 为 1 的用户信息。

**2. 抓包修改参数**
由于前端是下拉框，无法直接输入代码。开启 Burp Suite 拦截，选择 `2` 点击查询，抓取 POST 请求。将请求体中的 `id=2` 修改为：
```http
id=1 or 1=1&submit=查询
```

**3. 验证结果**
点击 `Forward` 放行请求。回到网页，发现页面不再只显示一个用户，而是把数据库中所有用户的姓名和邮箱（vince, allen, kobe 等）全部回显了出来。由于 `1=1` 恒成立，原本的 `WHERE id = 1 or 1=1` 查询条件被绕过，成功获取全表数据。

## 五、知识点解析
1. **数字型注入**：当后端将参数视为数字类型拼接到 SQL 语句中时（如 `WHERE id = $id`），不需要使用单引号闭合。直接使用 `or 1=1` 即可测试。
2. **逻辑绕过**：`or 1=1` 会将查询条件恒定为真，导致数据库返回表中的所有记录。这在 SQL 注入中常用于快速获取敏感数据。

## 六、总结与防御
**本题总结**：
数字型注入利用门槛极低。只要开发者没有对参数进行类型限制或预编译，一句简单的 `or 1=1` 就能导致全表数据泄露。

**安全防御建议**：
- **预编译语句 (PDO/Prepared Statements)**：将 SQL 语句与数据分离，这是防御 SQL 注入最有效的方法。
- **类型转换**：对于数字型参数，在服务端强制使用 `intval()` 等函数转换为整数。
- **最小权限原则**：限制数据库账号的权限，避免使用 root 账号连接数据库。
