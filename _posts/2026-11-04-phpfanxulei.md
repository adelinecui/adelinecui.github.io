## 一、题目信息
- 平台：Pikachu
- 分类：PHP反序列化 -> 概述/演示
- 难度：中等
- 通关说明：该关卡主要用于演示序列化数据的接收过程，由于靶场版本差异，部分环境不提供直接执行的实操利用，旨在理解 `unserialize()` 漏洞原理。

## 二、大白话原理讲解
**什么是序列化？**
就像你买了一个宜家柜子，商家不会把组装好的柜子寄给你，而是把木板、螺丝打包（序列化）成一个小包裹寄过去。在 PHP 中，`serialize()` 就是把一个对象变成一串文本字符串（如 `O:4:"User":1:{s:4:"name";s:5:"admin";}`）。

**什么是反序列化？**
你收到包裹后，按照说明书把柜子拼好（反序列化）。PHP 中的 `unserialize()` 就是把这串字符串重新变回对象。

**漏洞怎么产生？**
如果 PHP 类里定义了一些“魔法方法”（比如 `__destruct()` 会在对象销毁时自动执行，`__wakeup()` 会在反序列化时自动执行）。当你的恶意字符串被 `unserialize()` 还原时，这些魔法方法就会自动触发，从而执行你藏在里面的系统命令。

## 三、演示与排查

**1. 页面现象**
在“PHP反序列化概述”页面，输入框提示“这是一个接受序列化数据的api”。但在当前靶场版本中，直接输入无回显，说明该页面主要作为理论展示。

**2. 源码探测**
若在真实环境下测试，可以通过构造简单的测试字符串（如 `O:8:"stdClass":0:{}`）提交，观察报错信息。错误信息可能会暴露后端真实的类名和属性，这是构造 Payload 的关键。

**3. 构造 Payload 演示**
假设后端源码如下：
```php
class S {
    public $cmd;
    function __destruct() {
        system($this->cmd);
    }
}
$s = unserialize($_POST['data']);
```
我们只需在本地构造 `S` 类的序列化字符串：
```text
O:1:"S":1:{s:3:"cmd";s:6:"whoami";}
```
提交这段字符串，后端在反序列化并销毁对象时，就会自动执行 `whoami` 命令。

## 四、知识点解析
1. **反序列化漏洞**：当应用将用户可控的输入直接传递给 `unserialize()` 函数时，攻击者可以控制对象的属性，从而触发类中的危险魔术方法（`__destruct`、`__wakeup`、`__toString` 等）。
2. **利用条件**：需要找到具有危险魔术方法的类，并且能够控制该类的属性。

## 五、总结与防御
**本题总结**：
反序列化漏洞属于高危漏洞，一旦被利用可直接导致 RCE。本题由于靶场版本限制未进行实操，但掌握了原理即可。

**安全防御建议**：
- **避免反序列化用户输入**：尽量使用 JSON 等安全的数据格式进行传输。
- **签名与校验**：如果必须使用反序列化，应对序列化字符串进行加密签名，防止用户篡改。
- **限制类解析**：使用 `unserialize()` 的第二个参数 `allowed_classes` 来限制允许反序列化的类。
