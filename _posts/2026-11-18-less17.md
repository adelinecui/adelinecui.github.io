## 一、题目信息
- 平台：SQLi-Labs
- 分类：Web - SQL Injection
- 难度：中等偏上
- 通关标识：识别出密码重置功能中 `UPDATE` 语句的注入点，利用 `updatexml` 报错注入，并使用派生表绕过 1093 限制，爆出账号密码。

## 二、大白话原理讲解
之前的关卡，柜员（数据库）干的都是“查”数据的活儿（`SELECT`）。这一关，柜台变成了“密码重置”窗口，干的是“改”数据的活儿（`UPDATE`）。

出题人很狡猾：他知道你会去试用户名，所以给用户名加了防弹衣（过滤了引号）。但他忘了给**新密码**穿防弹衣。
于是，我们可以在“新密码”里填上“碰瓷”的咒语（`updatexml`），让他报错。

但这关有个大坑：改密码的指令是 `UPDATE users SET password='你的新密码' WHERE username='admin'`。
如果你直接在“新密码”里写 `select ... from users`，MySQL 会拒绝执行，因为它觉得“你正在修改这张表，又同时去查这张表，会死锁”（这就是臭名昭著的 1093 错误）。
怎么解决？用**“派生表”**（套娃）。我们先把密码查出来放在一个临时的地方，再告诉 MySQL：“我没查这张表，我查的是临时的地方”。这就完美绕过了限制。

## 三、解题步骤

**第一步：寻找并确认注入点**
在页面的 `Username` 填入 `admin`，在 `Password` 填入 `123'`。
页面报错：`You have an error in your SQL syntax; ... near ''123'' WHERE username='admin'' at line 1`。
**分析**：确认密码处存在单引号字符型注入。由于是 `UPDATE` 语句，后面不需要 `LIMIT`，使用 `#` 进行注释最稳妥。

**第二步：利用 updatexml 爆出表名**
在 `passwd` 处闭合后使用 `#` 截断后续代码，使用报错函数：
```sql
uname=admin&passwd=1' AND updatexml(1, concat(0x7e, (select group_concat(table_name) from information_schema.tables where table_schema='security')), 1) #
```
**回显现象**：报错信息泄露 `~emails,referers,uagents,users~`。

**第三步：利用派生表绕过限制提取数据**
直接查询 `users` 会报 `1093` 错误（不能同时更新和查询同一张表），将 Payload 修改为使用派生表：
```sql
uname=admin&passwd=1' AND updatexml(1, concat(0x7e, (select group_concat(username,0x3a,password) from (select * from users) as temp)), 1) #
```
**回显现象**：成功报错 `XPATH syntax error: '~Dumb:Dumb,Angelina:I-kill-you,D'`。数据因报错字符长度限制被截断，但核心账号密码已成功提取，通关。

## 四、踩坑记录与复盘
1. **注入点为什么在密码框？**
   后台代码中，`username` 被 `mysqli_real_escape_string()` 严格过滤，而 `passwd` 却没有。这就是典型的“防御盲区”。
2. **什么是派生表（Derived Table）？**
   在 SQL 中，`(select * from users) as temp` 就是派生表。它相当于把原表的数据复制了一份到内存里，再用外面的函数去查这份副本，从而绕过了 MySQL 对同一张表同时执行 `UPDATE` 和 `SELECT` 的限制。
3. **报错截断问题**
   `updatexml` 函数在报错时，回显的数据有长度限制（通常在 32 个字符左右）。如果数据太长，后面的内容会被截断。实战中可以通过 `substr` 分段截取，或者用 `limit` 一行行看。

## 五、总结与防御
**本题总结**：
Less-17 是一道非常经典的 `UPDATE` 注入题。核心在于找对注入参数（密码框），并掌握在 `UPDATE` 语句中使用派生表绕过 1093 错误的技巧。

**安全防御建议**：
- **一视同仁**：不能只过滤用户名而忽略密码字段，所有输入点必须使用预编译语句（PDO/MySQLi）处理。
- **关闭详细报错**：生产环境必须关闭 `display_errors`，防止 `updatexml` 等函数将数据带出。
