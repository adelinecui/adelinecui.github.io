## 一、题目信息
- 平台：Pikachu
- 分类：Cross-Site Scripting -> xss之过滤
- 难度：中等
- 通关标识：提交过滤绕过 Payload 后成功弹窗

## 二、考点
1. 黑名单过滤机制的原理与缺陷
2. XSS 标签替换与绕过技巧
3. HTML 事件属性（如 `onerror`）的利用

## 三、题目内容
页面提供了一个输入框。当尝试输入经典的 `<script>alert('XSS')</script>` 时，代码未能执行，且页面回显的内容缺失了 `<script>` 关键字。说明后端对特定的危险标签（如 script）进行了黑名单过滤。

## 四、解题步骤

**1. 确认过滤规则**
输入基础 Payload：
```html
<script>alert('XSS')</script>
```
提交后发现标签被后端直接替换或过滤，无法触发弹窗。

**2. 使用事件属性绕过**
既然黑名单只针对 `<script>` 标签，我们可以利用 HTML 中其他支持事件触发的标签。使用 `<img>` 标签，利用其加载失败时触发的 `onerror` 事件来执行 JavaScript 代码：
```html
<img src=1 onerror=alert('XSS')>
```
将此 Payload 输入并提交。由于 `src=1` 是一个无效的图片地址，浏览器加载失败后触发 `onerror` 事件，成功执行弹窗，绕过成功。

## 五、知识点解析
1. **黑名单过滤的局限性**：黑名单机制试图通过穷举已知的恶意标签或字符来进行拦截。但 HTML 标准中能够执行 JavaScript 的方式繁多（如 `onclick`、`onload`、`onerror` 等），只要漏掉一种，就会被攻击者利用。
2. **`onerror` 事件**：`<img>` 标签在遇到图片资源加载失败（如路径错误、资源不存在）时，会自动触发 `onerror` 属性中定义的 JavaScript 代码。这是绕过 `<script>` 过滤最常用的手法之一。

## 六、总结与防御
**本题总结**：
本题展示了黑名单过滤的脆弱性。攻击者可以通过寻找未被过滤的标签和事件，轻松绕过防御。

**安全防御建议**：
- **放弃黑名单**：永远不要试图穷举所有可能的恶意标签，因为 HTML 特性千变万化。
- **使用白名单**：在允许用户输入 HTML 的场景下，采用严格的标签白名单机制（如只允许 `<b>`、`<i>` 等安全标签）。
- **输出转义（核心）**：无论输入如何，在将数据输出到页面前，必须使用 `htmlspecialchars()` 等函数进行 HTML 实体编码，确保浏览器将其作为纯文本展示。
