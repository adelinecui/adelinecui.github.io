## 一、题目信息
- 平台：Pikachu
- 分类：SQL-Inject -> 搜索型注入
- 难度：简单
- 通关标识：通过闭合 `LIKE` 语句中的单引号和通配符，获取全表数据

## 二、考点
1. `LIKE` 模糊查询中的 SQL 注入
2. 闭合 `%'` 结构并利用注释符
3. 联合查询绕过

## 三、题目内容
页面提供一个搜索框，允许用户输入用户名的一部分进行模糊查询。后端 SQL 语句大概为：`SELECT * FROM users WHERE username LIKE '%$name%';`。

## 四、解题步骤

**1. 测试闭合**
输入单引号 `'`，页面报错。说明单引号破坏了 `LIKE '%...%'` 的结构。

**2. 注入万能条件**
为了绕过查询限制并防止报错，我们需要闭合单引号和百分号，构造 Payload：
```sql
' or 1=1 #
```
- `'`：闭合了前面的单引号。
- `or 1=1`：让查询条件恒真。
- `#`：注释掉后面的 `%'` 结构，防止语法错误。
点击搜索，页面成功回显所有用户的信息。

**3. 联合查询**
测试列数为 3 后，可以进一步注入：
```sql
' union select 1, database(), 3 #
```
成功回显当前数据库名。

## 五、知识点解析
1. **搜索型注入**：本质上属于字符型注入的一种变体。因为 `LIKE` 语句通常带有 `%` 通配符，所以在闭合时，我们只需要闭合掉单引号 `'`，后面的 `%'` 可以通过 `#` 注释掉。
2. **模糊查询注入**：在 `LIKE` 语句中，`%` 代表任意字符。攻击者可以利用 `%` 和单引号配合，突破原有的查询限制。

## 六、总结与防御
**本题总结**：
不论是 `=` 还是 `LIKE`，只要使用了字符串拼接，且未对用户输入进行过滤，就会产生 SQL 注入。

**安全防御建议**：
- **预编译语句 (Prepared Statements)**：最有效的防御手段。
- **过滤通配符和引号**：对于搜索功能，可以考虑在后端先对输入进行转义，或者禁止用户输入 `%` 和 `'` 等特殊字符。
- **最小权限原则**：数据库账号只给予必要的查询权限。
