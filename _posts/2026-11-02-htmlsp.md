## 一、题目信息
- 平台：Pikachu
- 分类：Cross-Site Scripting -> xss之htmlspecialchars
- 难度：中等
- 通关标识：利用单引号闭合 HTML 属性后成功弹窗

## 二、考点
1. `htmlspecialchars()` 函数的默认参数缺陷
2. HTML 属性逃逸与事件注入
3. XSS 防御的常见误区

## 三、题目内容
页面提供了一个输入框。后端使用了 PHP 的 `htmlspecialchars()` 函数对用户输入进行转义处理。然而，由于开发者未指定引号处理参数（默认 `ENT_COMPAT`），单引号并未被转义，从而导致了属性逃逸漏洞。

## 四、解题步骤

**1. 测试转义情况**
输入经典的 `<script>alert('XSS')</script>` 提交。页面会将其中的 `<` 和 `>` 转义为 `&lt;` 和 `&gt;`，导致标签无法解析，XSS 执行失败。这说明后端确实使用了转义函数。

**2. 测试单引号逃逸**
输入一个单引号 `'` 提交。观察页面源码，发现单引号原样输出了，并没有变成 `&#039;`。结合页面回显结构，输入很可能被放到了类似 `<a href='...'>` 这样的单引号属性中。

**3. 构造闭合 Payload**
既然单引号没有被转义，我们就可以提前闭合 `href` 属性，然后注入 `onclick` 事件。输入以下 Payload：
```html
' onclick='alert("XSS")
```
提交后，页面上会出现一个可点击的按钮（或链接）。点击该元素，成功执行 `alert("XSS")`，弹窗出现。

## 五、知识点解析
1. **`htmlspecialchars()` 的默认参数陷阱**：当只传入一个参数时，默认使用 `ENT_COMPAT`。它只转义双引号 `"`，**不转义单引号 `'`**。
2. **属性逃逸**：如果开发者将用户输入放在单引号包裹的 HTML 属性中（如 `href='...'`），而输入中的单引号未被转义，攻击者就能提前结束属性值，从而注入新的事件属性（如 `onclick`、`onmouseover`）。

## 六、总结与防御
**本题总结**：
使用了 `htmlspecialchars()` 并不等于绝对安全。开发者必须根据具体的上下文环境，正确设置函数的参数。

**安全防御建议**：
- **正确使用转义函数**：使用 `htmlspecialchars($str, ENT_QUOTES, 'UTF-8')`，其中 `ENT_QUOTES` 会同时转义单引号和双引号，最大程度防御属性逃逸。
- **输出到属性时的特殊处理**：在将数据输出到 HTML 属性时，确保任何可能闭合属性的字符都被正确处理。
- **部署 CSP**：配置内容安全策略（Content Security Policy），即使注入了内联事件，浏览器也可以拒绝执行。
