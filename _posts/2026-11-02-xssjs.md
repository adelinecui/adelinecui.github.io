## 一、题目信息
- 平台：Pikachu
- 分类：Cross-Site Scripting -> xss之js输出
- 难度：中等
- 通关标识：输入闭合变量的 Payload 后成功弹窗

## 二、考点
1. JavaScript 上下文中的 XSS 利用
2. 变量闭合与代码逃逸
3. JS 注释符在 XSS 中的妙用

## 三、题目内容
页面输入用户喜欢的 NBA 球员。查看源码发现，后端将用户的输入直接拼接到了 `<script>` 标签内部的 JavaScript 变量中，如 `var $name = '用户输入';`。

## 四、解题步骤

**1. 分析输出上下文**
由于输入被放进了 `<script>` 标签内的单引号中，常规的 `<script>` 或 `<img>` 标签都无法执行，因为 HTML 标签不能嵌套在 JS 代码字符串中。

**2. 构造闭合逃逸 Payload**
我们需要先跳出单引号的限制，构造如下 Payload：
```javascript
';alert('XSS');//
```
代码执行逻辑如下：
- `'`：闭合了 `var $name = '` 前面的单引号。
- `;`：结束变量赋值语句。
- `alert('XSS')`：执行恶意代码。
- `;`：结束弹窗语句。
- `//`：将后端原本拼接到后面的单引号 `'` 注释掉，防止引发 JS 语法错误。

**3. 触发弹窗**
将 Payload 输入并提交，页面刷新时，JavaScript 引擎解析执行拼合后的代码，成功弹出 `XSS` 提示框。

## 五、知识点解析
1. **JS 上下文 XSS**：当输出点在 `<script>` 标签内部时，攻击者不需要注入 HTML 标签，而是需要利用引号闭合和 JavaScript 语法来注入恶意代码。
2. **注释符绕过**：由于后端代码通常会拼接成 `var a = '输入';`，如果只闭合前面的引号，后面的单引号会导致语法错误。使用 `//` 或 `/* */` 可以注释掉后续的代码，确保 Payload 顺利执行。

## 六、总结与防御
**本题总结**：
XSS 防御不仅要处理 HTML 标签，还要注意 JavaScript 代码块中的变量输出。只要存在单引号闭合，且输入未转义，就会导致代码逃逸。

**安全防御建议**：
- **JS 变量输出转义**：在将用户数据输出到 JavaScript 变量时，应使用 JSON 编码（如 `json_encode()`）或专门的 JS 转义函数，切勿手动拼接单引号。
- **避免内联脚本**：尽量避免在 HTML 中直接写 `<script>` 标签的内联代码，使用外部 JS 文件，并通过 `data-` 属性或 AJAX 传递数据。
- **CSP 策略**：配置严格的内容安全策略，禁止执行未经授权的内联脚本。
