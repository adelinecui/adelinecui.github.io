## 一、题目信息
- 平台：Pikachu
- 分类：Cross-Site Scripting -> 反射型xss(get)
- 难度：简单
- 通关标识：页面弹出提示框

## 二、考点
1. 反射型 XSS（跨站脚本攻击）原理
2. GET 传参注入与浏览器解析机制
3. 基础 JavaScript 脚本注入

## 三、题目内容
页面包含一个输入框，提示 "Which NBA player do you like?"。当用户提交输入的内容后，后端通过 GET 请求接收参数，并将其直接回显到页面中，未对特殊字符进行过滤和转义。

## 四、解题步骤

**1. 测试输入**
在输入框中随意输入（如 `Kobe`），点击 submit。观察浏览器的 URL 变化，发现参数通过 GET 方式传递：
```text
http://127.0.0.1/pikachu/vul/xss/xss_reflected_get.php?message=Kobe&submit=submit
```

**2. 构造 Payload**
针对 `message` 参数，尝试构造基础的 XSS 弹窗代码。在输入框中输入：
```html
<script>alert('XSS')</script>
```
点击提交。

**3. 验证结果**
如果后端未做过滤，JavaScript 代码将被浏览器直接执行。页面成功弹出一个内容为 `XSS` 的对话框，证明漏洞存在，攻击成功。

## 五、知识点解析
1. **反射型 XSS**：非持久化 XSS。恶意代码没有保存在服务器端，而是通过 URL 参数（如 GET 请求）发送给服务器，服务器未经过滤直接“反射”回用户的浏览器并执行。通常需要诱导受害者点击包含恶意代码的链接。
2. **GET 传参**：本题中用户输入直接拼接在 URL 中，修改 URL 中的 `message` 参数即可注入任意脚本。

## 六、总结与防御
**本题总结**：
前端输入了危险字符 `<script>`，后端将其直接输出到 HTML 页面中，导致浏览器将其解析为可执行脚本并运行。

**安全防御建议**：
- **输入过滤**：在服务端和客户端对用户输入进行严格限制，过滤掉 `<`、`>`、`javascript` 等危险字符。
- **输出转义**：在将数据回显到 HTML 页面时，必须使用 HTML 实体编码（如将 `<` 转换为 `&lt;`），确保浏览器将其作为纯文本展示，而不是当作脚本执行。
- **设置 HttpOnly**：给关键的 Cookie 设置 `HttpOnly` 属性，防止 XSS 脚本窃取用户凭证。
