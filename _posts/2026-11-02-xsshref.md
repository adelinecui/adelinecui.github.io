## 一、题目信息
- 平台：Pikachu
- 分类：Cross-Site Scripting -> xss之href输出
- 难度：中等
- 通关标识：点击生成的恶意链接后成功弹窗

## 二、考点
1. HTML 输出上下文的理解
2. `javascript:` 伪协议的利用
3. 针对链接属性的 XSS 防御绕过

## 三、题目内容
页面提示用户输入常用的网站 URL 地址。后端获取输入后，将其直接拼接到了 `<a>` 标签的 `href` 属性中。由于输出点在属性内，传统的标签注入无法生效。

## 四、解题步骤

**1. 测试常规标签**
输入 `<script>alert('XSS')</script>` 提交。页面生成了链接，但点击后无任何反应，说明 `<script>` 标签在属性上下文中无法解析执行。

**2. 使用伪协议注入**
由于输入点位于 `href` 属性，我们可以利用 `javascript:` 伪协议。在输入框中输入：
```text
javascript:alert('XSS')
```
点击 `submit` 提交。

**3. 触发弹窗**
页面下方会生成一个名为“请自己点一下吧”的链接。用鼠标点击该链接，浏览器会解析并执行 `javascript:` 后的代码，成功弹出 `XSS` 提示框，通关。

## 五、知识点解析
1. **上下文决定 Payload**：XSS 的利用方式取决于数据在 HTML 中的输出位置。在 `href` 属性中，必须使用 `javascript:` 伪协议来执行代码。
2. **`javascript:` 协议**：一种特殊的伪协议，允许在 URL 中直接嵌入 JavaScript 代码。当用户点击包含该协议的链接时，浏览器会执行相应的脚本。

## 六、总结与防御
**本题总结**：
只要攻击者能控制 `href` 属性，且后端未对协议进行校验，就可以利用伪协议执行任意 JavaScript 代码。

**安全防御建议**：
- **协议白名单**：在处理用户输入的 URL 时，严格校验协议，只允许 `http:` 和 `https:`，禁止 `javascript:`、`data:` 等危险协议。
- **输出转义**：在将用户输入输出到 HTML 属性时，务必进行严格的实体编码。
- **内容安全策略 (CSP)**：配置 CSP 限制内联脚本和不受信任的脚本执行。
