## 一、靶场信息
- **漏洞类型**：数字型+单引号字符型注入（基于 GET 传参）、堆叠注入（Stacked Queries）。
- **防御机制**：从这一关开始，后端不再使用基础的 `mysql_query()`，而是使用了支持执行多条 SQL 语句的 `mysqli_multi_query()` 函数。
- **通关思路**：利用单引号闭合 `id` 参数，通过 `UNION SELECT` 联合查询爆出数据；同时利用 `mysqli_multi_query()` 的特性，使用分号 `;` 截断并执行第二条 SQL 语句（如插入、更新、删除），实现堆叠注入。

## 二、核心绕过思路（大白话解析）

这一关的页面提示告诉你输入数字 ID。尝试输入 `1'` 会发现报错，说明虽然外面看起来是数字，但后端 SQL 语句里其实给 `id` 加了单引号包裹。

这关最大的考点在于底层的函数变了。之前的关卡用的是 `mysqli_query()`，它一次只能执行一条 SQL 语句；而 Less-38 用的是 `mysqli_multi_query()`，这个函数允许用分号 `;` 隔开，**一次性执行多条 SQL 语句**。

这意味着，你不仅能像以前一样用 `UNION SELECT` 查数据，还能在分号后面写 `INSERT`、`UPDATE`、`DELETE`，甚至用 `SLEEP()` 等，防不胜防。

## 三、详细操作步骤与 Payload 解析

### 第一步：探测回显点

**Payload（直接浏览器地址栏输入）：**
```text
?id=-1' union select 1,2,3 --+
```

**回显现象：**
页面显示数字 `2` 和 `3`（说明 `id` 参数存在单引号闭合，且原查询有 3 列）。

**大白话解析：**
*   **`-1'`**：`-1` 让原查询落空，单引号 `'` 闭合后台语法。
*   **`union select 1,2,3`**：联合查询探测列数。
*   **`--+`**：注释符，把后台原本跟着的 `LIMIT` 等限制条件注释掉。

### 第二步：联合查询脱库（提取账号密码）

**Payload：**
```text
?id=-1' union select 1,group_concat(username,0x3a,password),3 from users --+
```

**回显现象：**
页面回显位成功爆出所有账号密码，如 `Dumb:Dumb,Angelina...`。

**大白话解析：**
*   把“超级打包机” `group_concat` 塞进第 2 列。
*   把 `users` 表里的账号密码全部打包，用冒号（`0x3a`）隔开，一次性全部打印在页面上。

### 第三步：堆叠注入演示（新增管理员）

由于 `mysqli_multi_query()` 支持多条语句，我们可以在原本的查询后面，直接追加一条 `INSERT` 语句。

**Payload：**
```text
?id=1';insert into users(id,username,password) values(100,'admin2','123456')--+
```

**回显现象：**
页面可能只显示正常的 `id=1` 的数据，但后台已经成功执行了插入操作。

**大白话解析：**
*   `?id=1'`：首先正常闭合第一条查询语句。
*   `;`：**核心！** 分号用于结束第一条 SQL 语句，告诉数据库后面还有一条。
*   `insert into users...`：执行第二条语句，往 `users` 表里强行插入一个 ID 为 100，账号为 `admin2`，密码为 `123456` 的用户。
*   `--+`：把后台剩下的单引号注释掉，防止语法错误。

*(注：验证是否插入成功，可以再次访问 `?id=100`，如果页面显示了 `admin2`，说明堆叠注入成功。)*

## 四、核心防御机制（Remediation）
- **禁用多语句执行**：在 PHP 中，尽量使用 `mysqli_query()` 而不是 `mysqli_multi_query()`，除非业务绝对需要一次性执行多条语句。
- **预编译语句（PDO/MySQLi）**：使用参数化查询，从根本上隔离代码与数据，避免拼接 SQL。
- **统一字符集**：将数据库和 Web 应用的字符集统一设置为 `UTF-8`，防止宽字节等编码问题绕过。
