## 一、题目信息
- 平台：Pikachu
- 分类：Cross-Site Scripting -> DOM型xss-x
- 难度：简单
- 通关标识：点击生成的超链接后弹窗

## 二、考点
1. DOM型 XSS 进阶理解
2. 前端 JavaScript 对 HTML 属性的拼接（如 `href`）
3. 标签闭合与 `onerror` 事件触发绕过

## 三、题目内容
页面提供了一个输入框和“请说出你的伤心往事”按钮。与前一关不同，提交内容后页面并未直接触发弹窗，而是将用户输入的内容生成为了一个可点击的链接。漏洞点隐藏在该链接的生成过程中。

## 四、解题步骤

**1. 尝试基础注入**
在输入框输入 `<script>alert(1)</script>` 或 `<img src=1 onerror=alert(1)>`，点击按钮，页面没有反应。这说明前端并没有直接将内容通过 `innerHTML` 渲染到页面主体，而是将其拼接到了某个标签的属性中（通常是 `<a>` 标签的 `href` 属性）。

**2. 构造闭合 Payload**
为了跳出属性的限制并注入新的标签，我们使用单引号 `'` 和右尖括号 `>` 闭合原有的代码结构：
```html
'><img src=1 onerror=alert(1)>
```
将此 Payload 输入框中并点击按钮。

**3. 触发执行**
此时页面下方会生成一行文字（或一个链接）。用鼠标点击该生成的链接，浏览器尝试加载 `src=1` 失败，触发 `onerror` 事件，成功执行 `alert(1)`，页面弹窗，漏洞利用成功。

## 五、知识点解析
1. **属性注入与闭合**：当输入被限制在 `<a href="输入内容">` 这样的属性中时，直接注入 `<script>` 是无效的。需要先使用 `'` 或 `"` 闭合属性，再用 `>` 闭合标签，才能插入新的恶意标签。
2. **二次触发**：DOM型 XSS 的触发方式取决于代码怎么写。本关将 Payload 变成了链接，需要用户产生点击行为才会触发解析和执行。

## 六、总结与防御
**本题总结**：
DOM型 XSS 的利用方式非常灵活。本题的关键在于识别出输入被拼接到了链接属性中，并通过标签闭合手法成功逃逸。

**安全防御建议**：
- **属性值转义**：在将用户输入拼接到 HTML 属性（如 `href`、`src`）时，必须对引号、尖括号等进行严格的 HTML 实体编码。
- **协议白名单**：如果业务需要用户输入链接，应严格限制协议（如仅允许 `http://` 或 `https://`），禁止使用 `javascript:` 等伪协议。
- **使用安全的 DOM API**：尽量使用 `textContent` 操作文本，避免直接拼接 HTML 字符串。
