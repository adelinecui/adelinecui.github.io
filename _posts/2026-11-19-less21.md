## 一、题目信息
- 平台：SQLi-Labs
- 分类：Web - SQL Injection
- 难度：中等
- 通关标识：识别出 Cookie 的值被 Base64 编码，利用 `')` 闭合，将 Payload 编码后填入 Cookie 实现联合查询注入。

## 二、大白话原理讲解
这关是第 20 关的“进阶版”。不仅柜员（数据库）要查你的“手环”（Cookie），他还给你加了一道“保密”工序——**Base64 编码**。

你正常登录后，后台会把你的用户名 `admin` 变成乱码 `YWRtaW4=` 存进 Cookie。你刷新页面时，后台先把这个乱码解码成 `admin`，然后再去查数据库。
既然它要解码，我们只要**先把 SQL 注入的咒语编码成乱码，再填进 Cookie**，后台解码后就会乖乖执行我们的咒语。

另外，这关的锁孔变成了**单引号加括号 `')`**，千万别漏掉括号。

## 三、解题步骤

**1. 正常登录，查看 Cookie 特征**
在登录框输入 `admin` / `admin`，登录成功后按 `F12` 查看 `Application` -> `Cookies`。
发现 `uname` 的值变成了类似 `YWRtaW4=` 的乱码，确认存在 Base64 编码。

**2. 制作并编码 Payload**
因为锁孔是 `')`，构造测试回显位的 Payload：
```text
-1') union select 1,2,3 #
```
把这个 Payload 拿去在线网站（或 HackBar）进行 Base64 编码，得到：
```text
LTEnKSB1bmlvbiBzZWxlY3QgMSwyLDMgIw==
```

**3. 替换 Cookie 并刷新**
在 F12 里，把 `uname` 的值替换成上面那串编码后的乱码，按回车保存，然后 `F5` 刷新页面。
**现象**：页面回显 `Your Login name:2` 和 `Your Password:3`，说明回显点被成功控制。

**4. 终极拖库**
构造查账号密码的 Payload：
```text
-1') union select 1,group_concat(username,0x3a,password),3 #
```
**重新进行 Base64 编码**（注意，每次改 Payload 都要重新编码），得到的字符串填入 Cookie 的 `uname` 中，刷新页面。
成功爆出所有账号密码。

## 四、踩坑记录与复盘
1. **Base64 编码的时机**
   你必须先构造好完整的 Payload，然后再编码。千万不要先编码再拼接，否则拼接出来的字符会被后台当成非法 Base64 报错。
2. **括号陷阱**
   导图明确提示了 `single quotes and parenthesis`（单引号和括号）。如果不加括号，Payload 是 `-1' union select...`，会导致后台 SQL 语法错误。

## 五、总结与防御
**本题总结**：
Less-21 引入了 Base64 编码，这也是实战中常见的“弱混淆”手段。只要认出 Base64 的特征（结尾的 `=`），利用工具先编码后注入，就能轻松绕过。

**安全防御建议**：
- **不要依赖 Base64 混淆**：Base64 不是加密，只是编码。后端必须在查询前使用预编译语句。
- **Cookie 签名**：防止攻击者篡改 Cookie 内容。
