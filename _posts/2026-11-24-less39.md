## 一、靶场信息
- **漏洞类型**：数字型注入（GET 传参）、堆叠注入（Stacked Queries）。
- **防御机制**：后端未对传入的 `id` 参数加引号包裹，直接将其拼接进 SQL 语句，且底层使用了支持执行多条语句的 `mysqli_multi_query()` 函数。
- **通关思路**：直接利用数字型特性，使用 `UNION SELECT` 联合查询爆出数据；同时利用 `mysqli_multi_query()` 支持多条语句的特性，使用分号 `;` 截断并执行第二条 SQL 语句实现堆叠注入。

## 二、核心绕过思路（大白话解析）

这一关的页面提示和 Less-38 几乎一模一样，但底层逻辑有个关键变化：**Less-38 是字符型（带单引号），而 Less-39 是纯数字型**。

你在地址栏输入 `?id=1'` 会发现页面报错或者查不出东西，但输入 `?id=1` 却是正常的。这就说明后端代码大概是 `SELECT * FROM users WHERE id = $id`，参数没有被单引号包裹。既然是数字型，就省去了闭合单引号的麻烦，直接上 `UNION SELECT` 即可。

同时，这关和 38 关一样，底层用的是 `mysqli_multi_query()`，这意味着我们不仅能联合查询，还能用分号 `;` 隔开，执行 `INSERT`、`UPDATE`、`DELETE` 等任意 SQL 语句，也就是**堆叠注入**。

## 三、详细操作步骤与 Payload 解析

### 第一步：探测回显点

**Payload（直接浏览器地址栏输入）：**
```text
?id=-1 union select 1,2,3 --+
```

**回显现象：**
页面显示数字 `2` 和 `3`，确认原查询有 3 列，且第 2、3 列存在回显。

**大白话解析：**
*   **`-1`**：让原查询落空，把页面回显位空出来。
*   **`union select 1,2,3`**：联合查询，强行让数据库多返回 3 列数据，测试哪一列会显示在页面上。
*   **`--+`**：注释符，把后台原本跟着的 `LIMIT` 等限制条件注释掉。

### 第二步：联合查询脱库（提取账号密码）

**Payload：**
```text
?id=-1 union select 1,group_concat(username,0x3a,password),3 from users --+
```

**回显现象：**
页面第 2 个回显位成功爆出所有账号密码，如 `Dumb:Dumb,Angelina...`。

**大白话解析：**
*   **`group_concat(username,0x3a,password)`**：超级打包机。把 `users` 表里的用户名和密码全部取出来，中间拼上冒号（`0x3a` 是冒号的十六进制），拼接成一个长字符串。
*   把它塞进第 2 列（因为我们第一步确认了第 2 列有回显），就能一次性把所有数据打印在页面上。

### 第三步：堆叠注入演示（新增管理员）

由于 `mysqli_multi_query()` 支持多条语句，我们可以在原查询结束后，用分号追加一条 `INSERT` 语句。

**Payload：**
```text
?id=1;insert into users(id,username,password) values(101,'admin3','123456')--+
```

**回显现象：**
页面可能只显示正常的 `id=1` 的用户信息，但后台已经成功执行了插入操作。

**大白话解析：**
*   **`?id=1`**：先让第一条 SQL 正常执行（不报错）。
*   **`;`**：**核心！** 分号用于结束第一条 SQL 语句。
*   **`insert into users...`**：执行第二条语句，往 `users` 表里强行插入一个 ID 为 101，账号为 `admin3`，密码为 `123456` 的用户。
*   **`--+`**：把后台剩下的语句注释掉，防止语法错误。

*(注：验证是否插入成功，可以再次访问 `?id=101`，如果页面显示了 `admin3`，说明堆叠注入成功。)*

## 四、核心防御机制（Remediation）
- **严格类型转换**：既然 `id` 是数字，在 PHP 中强制使用 `intval($_GET['id'])` 或 `(int)$_GET['id']` 进行类型转换，彻底杜绝注入。
- **禁用多语句执行**：在 PHP 中，尽量使用 `mysqli_query()` 而不是 `mysqli_multi_query()`，除非业务绝对需要。
- **预编译语句（PDO/MySQLi）**：使用参数化查询，从根本上隔离代码与数据。
