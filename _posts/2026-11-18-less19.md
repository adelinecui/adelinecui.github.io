## 一、题目信息
- 平台：SQLi-Labs
- 分类：Web - SQL Injection
- 难度：中等
- 通关标识：识别出注入点在 HTTP 请求头的 `Referer` 字段，利用 `updatexml` 触发报错注入。

## 二、大白话原理讲解
这关和第 18 关是“双胞胎”。前台登录框依然防守严密，我们还得靠抓包去偷偷修改浏览器的“证件”（请求头）。

区别在于：上一关后台记录的是你的“浏览器型号”（`User-Agent`），这一关后台记录的是你是从哪个网页跳转过来的（`Referer`）。
因为后台对 `Referer` 没有做过滤，我们只要把抓包工具里的 `Referer` 值改成报错注入的咒语（`updatexml`），就能让数据库“疼”得叫出声来，把账号密码喊出来。

## 三、解题步骤

**1. 正常登录并抓包**
*   在登录框输入用户名 `admin`，密码 `admin`。
*   用 Burp Suite 或 HackBar 拦截登录请求。

**2. 修改 Referer 触发报错**
在请求头中找到 `Referer: http://127.0.0.1/sqli-labs-master/Less-19/`。
把 `Referer` 的值替换为我们的 Payload：
```text
Referer: http://127.0.0.1/sqli-labs-master/Less-19/' AND updatexml(1,concat(0x7e,(select concat(username,0x3a,password) from users limit 0,1),0x7e),1), 1, 1) #
```
*(注意：同样是因为后台 INSERT 语句有 3 列，我们需要补齐 `, 1, 1)`，并用 `#` 注释掉后面的代码)*

**3. 验证结果**
放行请求后，页面会出现类似于第 18 关的回显或报错信息：
```text
Referer is: http://127.0.0.1/...' AND updatexml...
Truncated incorrect DOUBLE value: 'http://127.0.0.1/...'
```
只要看到了 `Truncated incorrect DOUBLE value` 或者 `XPATH syntax error`，就说明 `Referer` 注入成功，且 `updatexml` 函数已成功执行。

## 四、踩坑记录与复盘
1. **Referer 的格式**
   `Referer` 的值原本是一个 URL。我们在注入时，必须保留前面的 URL 部分，把 Payload 拼接在 URL 结尾或者路径里。比如 `http://127.0.0.1/' AND updatexml(...) #`。
2. **闭合与补列**
   和第 18 关一样，后端代码是 `INSERT INTO referers (referer, ip_address, username) VALUES ('$uagent', '$ip', '$username')`，所以一定要构造 `, 1, 1)` 来补齐列数。

## 五、总结与防御
**本题总结**：
Less-19 是 Less-18 的变体。不论是 `User-Agent` 还是 `Referer`，只要后端将其未经过滤拼接进 SQL 语句，就必然存在 Header 注入风险。掌握 Header 注入，在实际渗透测试中非常实用。

**安全防御建议**：
- **统一过滤**：不要只防着表单输入，HTTP 请求头的所有参数都必须经过严格转义。
- **关闭详细报错**：生产环境必须关闭数据库详细报错，防止被报错注入利用。
