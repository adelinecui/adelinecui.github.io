## 一、题目信息
- 平台：Pikachu
- 分类：RCE -> exec "eval"
- 难度：简单
- 通关标识：提交 `phpinfo();` 或系统命令后，被 PHP 成功执行。

## 二、大白话原理讲解：什么是 PHP 代码执行？
上一关是让服务器执行操作系统的命令（比如 `ping`），而这一关更严重。后端代码里使用了 PHP 的 `eval()` 函数。
`eval()` 的可怕之处在于：它会把用户输入的**字符串**，直接当成 **PHP 代码**来解析执行。
这就好比你去面试，面试官不仅看了你的简历（字符串），还直接把你写的未来规划（代码）当成现实去实施了。

## 三、解题步骤

**1. 验证代码执行**
在输入框中输入标准的 PHP 探针代码：
```php
phpinfo();
```
点击提交。页面成功渲染出了 PHP 的详细配置信息（版本、路径、模块等），证明代码被成功执行。

**2. 执行系统命令**
既然能执行 PHP，那我们就可以利用 PHP 的 `system()` 函数来调用系统底层命令：
```php
system('whoami');
```
或查看 Linux 根目录（Windows 换成 `dir C:\\`）：
```php
system('ls /');
```
页面均能正常回显命令执行结果。

## 四、知识点解析
1. **代码执行漏洞**：当应用将用户输入传给 `eval()`、`assert()`、`create_function()` 等函数时，如果未做严格过滤，攻击者就可以执行任意 PHP 代码。
2. **危害**：代码执行漏洞的权限通常极高，攻击者可以通过 PHP 代码调用系统函数（如 `system`、`exec`），进而控制整个服务器，或者写入 WebShell 后门。

## 五、总结与防御
**本题总结**：
`eval()` 是一把极其危险的双刃剑。只要用户能控制传入 `eval()` 的内容，服务器就等同于“裸奔”。

**安全防御建议**：
- **绝对禁止**：在业务代码中绝对不要使用 `eval()` 函数去执行用户输入的内容。
- **禁用危险函数**：在 `php.ini` 中禁用 `eval`、`system`、`exec` 等危险函数（`disable_functions`）。
- **严格的输入校验**：如果业务必须使用动态执行，必须使用严格的白名单校验，确保输入只包含预期的安全字符。
