## 一、题目信息
- 平台：Pikachu
- 分类：暴力破解 -> 验证码绕过(on client)
- 难度：简单
- 通关标识：页面回显 `login success`

## 二、考点
1. 前端验证码校验逻辑漏洞
2. 抓包修改/丢弃参数绕过前端限制
3. Burp Suite Intruder 模块的基础使用

## 三、题目内容
该关卡同样包含 Username、Password 和验证码输入框。但与前关不同的是，这里的验证码校验逻辑（甚至是存在性校验）仅仅写在了前端（JavaScript）中。只要绕过前端，后端实际上并不校验验证码的正确性，或者我们直接删掉验证码参数，即可实现暴力破解。

## 四、解题步骤

**1. 分析验证码机制**
在网页中随意输入账号密码和错误验证码，发现会弹窗提示验证码错误，阻止提交。这说明验证是在前端（JS）完成的。
如果我们在浏览器中禁用 JavaScript，或者通过抓包工具修改/删除验证码参数，就能绕过这个限制。

**2. 抓包并删除验证码参数**
开启 Burp Suite 拦截，输入正确的验证码（如截图中的 `ILR8T`），以及任意账号密码，点击登录。
在 Burp 中捕获到 POST 请求，找到请求体：
```http
username=admin&password=123&vcode=ILR8T
```
直接将 `&vcode=ILR8T` 这整个部分删除，将请求体修改为：
```http
username=admin&password=123
```
将其发送至 `Intruder` 模块。

**3. 设置攻击载荷**
在 `Positions` 标签页，清除默认标记，选中 `password` 的值 `123`，点击 `Add §` 将其设为变量。
```http
username=admin&password=§123§
```

**4. 配置字典并开始爆破**
进入 `Payloads` 标签页，`Attack type` 选择 `Sniper`。
在 `Payload set 1` 中加载密码字典（如 `123456`、`admin` 等）。
点击 `Start attack` 开始爆破。

**5. 分析结果**
由于请求中根本没有 `vcode` 参数，服务端完全没有进行验证码校验，直接进入账号密码比对逻辑。
观察爆破结果，寻找响应长度（Length）不同的一条请求，查看其 Response，发现返回了 `login success`，爆破成功。

## 五、知识点解析
1. **客户端校验的脆弱性**：任何仅依靠前端 JavaScript 进行的验证（如验证码、邮箱格式、敏感词过滤等）都是不可信的。攻击者可以随时禁用 JS、修改前端代码或直接使用抓包工具构造 HTTP 请求绕过。
2. **逻辑漏洞**：后端代码在接收登录请求时，如果没有强制检查 `vcode` 参数是否存在且正确，就会导致即使前端有验证码，后端依然裸奔。

## 六、总结与防御
**本题总结**：
遇到前端的验证码弹窗，不要被表象迷惑，直接抓包尝试删除或修改 `vcode` 字段。如果后端没有做二次校验，即可轻松绕过。

**安全防御建议**：
- **所有安全校验必须在服务端进行**。前端只负责展示，绝不能作为安全判断的唯一依据。
- 服务端在处理登录请求时，必须强制检查验证码参数的存在性、正确性和时效性。
- 确保验证码一次性使用。
