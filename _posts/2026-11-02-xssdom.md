## 一、题目信息
- 平台：Pikachu
- 分类：Cross-Site Scripting -> DOM型xss
- 难度：简单
- 通关标识：点击按钮后页面弹窗

## 二、考点
1. DOM型 XSS（基于文档对象模型）原理
2. 前端 JavaScript 的安全缺陷
3. 标签闭合与 `onerror` 事件触发绕过

## 三、题目内容
页面包含一个输入框和一个 `click me!` 按钮，下方显示 "what do you see?"。该关卡不涉及后端服务器处理，完全依赖前端 JavaScript 将用户输入的内容动态渲染到页面中。

## 四、解题步骤

**1. 测试基础注入**
输入 `<script>alert(1)</script>` 并点击按钮，发现未触发弹窗。说明前端使用了类似 `innerHTML` 的方式渲染，浏览器出于安全机制拦截了通过该方式插入的 `<script>` 标签。

**2. 尝试事件触发**
输入 `<img src=1 onerror=alert(1)>`，发现仍未弹窗。这说明前端代码可能将输入拼接到了某个标签的属性中（例如 `<a href="输入内容">`），导致我们输入的标签无法正常闭合和解析。

**3. 构造闭合 Payload 绕过**
为了跳出原有的标签限制，我们使用单引号 `'` 和右尖括号 `>` 来破坏并闭合前端的代码结构：
```html
'><img src=1 onerror=alert(1)>
```
将这串代码输入框中并点击提交。`'` 闭合了原有的属性引号，`>` 闭合了原有的标签。随后插入的 `<img>` 标签因找不到图片资源触发 `onerror` 事件，成功执行 `alert(1)`，页面弹窗，漏洞利用成功。

## 五、知识点解析
1. **DOM 型 XSS**：数据流向为 URL/输入框 -> 前端 JS 处理 -> DOM 渲染。漏洞完全发生在客户端浏览器中，不经过服务端解析。
2. **标签闭合**：当输入被限制在特定的 HTML 标签或属性中时，攻击者可以使用 `'`、`"`、`>` 等符号提前结束当前上下文，从而注入新的恶意标签。
3. **`onerror` 事件**：`<img>` 标签在图片加载失败时会触发 `onerror` 事件。由于 `<script>` 标签常被过滤或限制，使用 `img` 配合 `onerror` 是绕过 XSS 防御的常用手法。

## 六、总结与防御
**本题总结**：
DOM 型 XSS 提醒我们，前端的数据处理同样至关重要。通过标签闭合和事件触发，可以绕过基础的 `<script>` 防护。

**安全防御建议**：
- **使用安全的 DOM API**：避免使用 `innerHTML`，改用 `textContent` 或 `innerText`。
- **严格的输入校验与输出转义**：对用户输入的危险字符（如 `<`、`>`、`'`、`"`）进行 HTML 实体编码处理。
- **使用安全的前端框架**：现代框架默认自带转义机制，能有效预防此类漏洞。
