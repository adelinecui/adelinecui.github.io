## 一、题目信息
- 平台：Pikachu
- 分类：暴力破解 -> token防爆破?
- 难度：中等
- 通关标识：页面回显 `login success`

## 二、考点
1. 动态 Token 防爆破机制原理
2. Burp Suite 宏（Macros）与 Session 处理
3. Intruder 模块的 Pitchfork (草叉) 攻击模式提取动态值

## 三、题目内容
该关卡在表单中加入了一个隐藏字段（Hidden Input）`token`。每次页面加载或提交失败后，服务端的 Token 都会发生变化。这意味着我们不能使用固定的验证码或简单地删除参数。必须实现“提取上一个请求返回的新 Token -> 放入下一个请求中提交”的自动化流程，才能真正进行爆破。

## 四、解题步骤

**1. 分析页面与请求**
查看页面源码，发现表单中包含 `token` 字段。每次点击 Login 刷新页面，该值都会改变。
开启 Burp 抓包，随便提交一次，请求体为：
```http
username=admin&password=123&token=914a2b... (一串随机字符)
```
这个 `token` 每次提交后立即失效。

**2. 配置 Burp Session (提取动态 Token)**
为了自动获取最新的 Token 并填入爆破请求，我们需要借助 Burp Suite 的宏功能：
- 在 Burp 顶部菜单栏选择 `Project options` -> `Sessions`。
- 在 `Macros` 区域点击 `Add`，创建一个新的宏（命名为 `get_token`）。
- 然后**手动在浏览器刷新一下页面**，在 Burp 抓包历史（Proxy -> HTTP history）里找到那个 GET 请求（通常包含 `token=xxx` 隐藏在 HTML 源码里）。选中它，点击 OK。
- 在弹出的 `Macro Recorder` 窗口中，点击 `Configure item`，添加一个 `Custom parameter locations in response` -> 选择 `Regex`（正则），输入正则表达式提取 Token（比如：`name="token" value="(.*?)"`），然后给这个变量命名为 `mytoken`。点击 OK 保存宏。

**3. 配置 Session 处理规则**
- 在 `Sessions` 的 `Session Handling Rules` 点击 `Add`。
- 在 `Details` 页面，将 `Tool scope` 选为 `Intruder`。
- 在 `Rule Actions` 中点击 `Add` -> `Run a macro`。
- 选择刚才创建的宏 `get_token`。
- 在下方 `Update only the following parameters` 中，勾选 `mytoken`，并填入请求体中的参数名 `token`。这样系统就会自动把提取到的最新 Token 填到请求的 `token` 字段里。

**4. 设置 Intruder 载荷**
- 回到 Intruder 的 `Positions` 页面，将请求体里的 `username`、`password` 和 `token` 字段分别添加 `§` 标记。
- 在 `Payloads` 页面，`Attack type` 选择 `Pitchfork`（草叉）。
- `Payload set 1`：填入用户名字典（比如就一个 `admin`）。
- `Payload set 2`：填入密码字典。
- `Payload set 3`：**填入任意占位符（比如 `null`），因为真正的 Token 值会被宏（Macros）在发送前动态替换掉**。

**5. 开始爆破并分析**
点击 `Start attack` 开始爆破。
观察结果，找到响应长度（Length）不同的一条。通常这条请求的响应会返回 `login success`，爆破成功。

## 五、知识点解析
1. **Token 机制的正确防御逻辑**：每次页面加载生成一个随机 Token，提交时服务端校验 Token。校验后立即销毁旧 Token 并下发新的 Token。这样攻击者如果使用重放攻击（固定 Token）就会失败。
2. **Burp Suite 宏 (Macros) 的妙用**：面对动态变化的参数（如 Token），常规的字典爆破失效。可以通过宏自动发起一次请求，正则匹配提取响应中的新 Token，然后再将这个 Token 拼接到实际的爆破请求中，实现全自动化。

## 六、总结与防御
**本题总结**：
这是暴力破解的高级形式。核心在于熟练掌握 Burp Suite 的宏（Macro）抓取动态 Token，并利用 `Pitchfork` 模式配合占位符，让 Burp 自动实现“获取 Token -> 携带新 Token 请求”的循环。

**安全防御建议**：
- Token 必须是完全随机的，且每次使用后立即失效。
- 不能仅依靠 Token 防爆破，必须加上 IP 限制、请求频率限制或图形验证码。
- 确保 Token 与当前用户的会话绑定，防止跨站伪造。
