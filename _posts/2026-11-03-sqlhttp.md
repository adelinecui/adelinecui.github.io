## 一、题目信息
- 平台：Pikachu
- 分类：SQL-Inject -> "http header"注入
- 难度：中等
- 通关标识：修改 HTTP 请求头（如 `User-Agent`），成功触发 SQL 报错并获取数据库名

## 二、考点
1. HTTP 请求头注入原理
2. `updatexml()` 报错注入
3. 利用浏览器控制台（Console）重放并修改请求

## 三、题目内容
页面提供常规的登录功能。后端在处理登录逻辑时，会将获取到的 HTTP 请求头（如 `User-Agent` 或 `X-Forwarded-For`）存储到数据库中以便记录日志。由于未对请求头进行过滤，导致 SQL 注入漏洞。

## 四、解题步骤

**1. 正常登录并观察回显**
输入任意账号密码（如 `admin` / `123`）登录成功。页面回显了当前请求的 IP 地址、User-Agent、HTTP Accept 等信息，证明后端读取并处理了请求头。

**2. 抓取并修改请求**
由于输入框无法控制 HTTP 头，我们需要抓包修改。这里可以直接使用浏览器开发者工具（F12）的 Console 进行请求重放：
- 按 `F12` 打开开发者工具，切换到 `Network`（网络）标签，找到刚才登录的请求，右键选择 `Copy as fetch`。
- 切换到 `Console`（控制台）标签，粘贴代码，并修改请求头中的 `User-Agent` 字段：
```javascript
fetch("http://127.0.0.1/pikachu/vul/sqli/sqli_header/sqli_header.php", {
  "headers": {
    "User-Agent": "1' or updatexml(1,concat(0x7e,database()),0) or '"
  }
}).then(r => r.text()).then(console.log);
```
*(注：这里的 Payload 使用了单引号闭合，并利用 `updatexml` 函数构造 XPath 语法错误来爆出数据库名。)*

**3. 验证结果**
执行代码后，刷新页面或在控制台查看打印出的 Response 源码。如果在返回内容中看到了类似以下的报错信息：
```text
XPATH syntax error: '~pikachu'
```
说明 `User-Agent` 中的恶意代码被成功拼接到了 SQL 语句中执行，成功获取当前数据库名为 `pikachu`。

*(注：如果 `User-Agent` 未生效，可尝试将注入点更换为 `X-Forwarded-For` 头再次测试)*

## 五、知识点解析
1. **HTTP 头注入**：很多网站会记录访客的 `User-Agent`、`Referer` 或 `X-Forwarded-For`（客户端 IP）。如果这些请求头被直接拼接到 SQL 查询中且未做安全处理，就会形成注入点。
2. **报错注入**：利用 `updatexml()` 等 XML 函数强制制造语法错误，并将查询结果（如数据库名）通过错误信息回显出来。

## 六、总结与防御
**本题总结**：
HTTP 请求头同样属于“用户输入”，后端必须像处理表单参数一样，对请求头内容进行严格的过滤或预编译处理。

**安全防御建议**：
- **预编译语句**：在记录日志或进行数据库操作时，使用参数化查询（PDO 预处理）。
- **严格过滤**：对所有的 HTTP 头（包括 User-Agent、Referer、X-Forwarded-For 等）进行特殊字符过滤和长度限制。
- **关闭错误回显**：生产环境中关闭数据库报错回显，防止敏感数据泄露。
