## 一、题目信息
- 平台：Pikachu
- 分类：Cross-Site Scripting -> 反射型xss(post)
- 难度：简单
- 通关标识：页面弹窗执行 `alert`

## 二、考点
1. POST 方式的反射型 XSS
2. 前端输入点与后端回显点的寻找
3. JavaScript 脚本的注入与执行

## 三、题目内容
页面提供了一个登录表单，并通过 POST 方式提交数据。后端接收数据后，未进行过滤就直接将其回显到了页面上。

## 四、解题步骤

**1. 正常登录系统**
由于 Pikachu 靶场的机制，需要先登录才能进行后续操作。输入账号（如 `admin`）和密码（如 `123456`）正常登录。

**2. 寻找输出回显点**
登录成功后，页面会显示一个输入框（如“Which NBA player do you like?”）。这个输入框就是我们的注入点。

**3. 注入 Payload**
在输入框中直接输入经典的 XSS 测试代码：
```html
<script>alert('xss')</script>
```
点击 `submit` 提交。

**4. 验证结果**
由于后端没有对输入进行过滤，代码被原样输出到了 HTML 页面中。浏览器将其解析为可执行的 JavaScript 代码，页面成功弹出 `xss` 对话框，证明漏洞存在并利用成功。

## 五、知识点解析
1. **反射型 XSS**：非持久化 XSS。恶意代码没有保存在服务器端，而是通过请求发送给服务器，服务器未经过滤直接“反射”回用户的浏览器并执行。
2. **Session 共享**：在 Pikachu 靶场中，一次成功登录后，Session 会在整个 XSS 模块中保持有效，方便测试人员直接在各个关卡中寻找注入点。

## 六、总结与防御
**本题总结**：
本题的关键在于找到页面的回显位置。只要后端对用户的输入没有进行严格的过滤，直接将 `<script>` 标签原样输出，就会导致脚本被执行。

**安全防御建议**：
- **输出转义**：在将用户数据输出到 HTML 页面时，必须使用 HTML 实体编码（如将 `<` 转换为 `&lt;`），确保浏览器将其作为纯文本展示。
- **设置 HttpOnly**：给关键的 Cookie 设置 `HttpOnly` 属性，防止 XSS 脚本窃取用户凭证。
